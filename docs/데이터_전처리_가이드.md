# RAG 데이터 전처리 가이드

## 1. 목적

챗봇은 `사료로 본 한국사`, `신편 한국사`, `한국사 이미지 자료`를 기반으로 하이브리드 RAG 검색을 수행한다.

세 자료는 원본 구조가 서로 다르기 때문에, 챗봇에서 공통으로 사용할 수 있도록 `documents`와 `chunks` 형태의 JSONL 파일로 전처리한다.

## 2. 입력 데이터 위치

```text
storage/postgre/
  사료로 본 한국사/
  신편 한국사 csv/
  한국사 이미지 자료/
```

Docker 인프라 파일은 `storage/` 아래에 둔다.

```text
storage/
  docker-compose.yml
  init.sql
```

각 자료의 역할은 다음과 같다.

| 자료 | 성격 | 챗봇 활용 |
|---|---|---|
| 사료로 본 한국사 | 국문 번역, 원문, 해설 중심 | 근거성 높은 사료 기반 답변 |
| 신편 한국사 | 긴 서술형 개설 자료 | 개념 설명, 배경 설명, 시대 흐름 |
| 한국사 이미지 자료 | 이미지 설명과 메타데이터 | 관련 이미지 추천, 이미지형 문제 생성 보조 |

## 3. 출력 데이터 위치

전처리 결과는 아래 폴더에 생성된다.

```text
storage/postgre/processed/
```

생성 파일:

```text
historical_sources.documents.jsonl
historical_sources.chunks.jsonl

new_history.documents.jsonl
new_history.chunks.jsonl

image_materials.documents.jsonl
image_materials.chunks.jsonl
```

## 4. 전처리 스크립트

스크립트 위치:

```text
storage/postgre/scripts/
  rag_metadata.py
  preprocess_historical_sources.py
  preprocess_new_history.py
  preprocess_image_materials.py
```

`rag_metadata.py`는 세 전처리 스크립트에서 공통으로 사용하는 metadata 태깅 헬퍼이다.

주요 역할:

```text
- category_tags 생성
- chronology 생성
- 시대명, 왕조명, 연도 범위 정규화
- 제목/목차/분야/키워드 기반 검색 태그 조립
```

### 4.1 사료로 본 한국사

실행:

```powershell
.\.venv\Scripts\python.exe storage\postgre\scripts\preprocess_historical_sources.py
```

처리 내용:

```text
- csv 폴더의 CSV 파일 로드
- 국문, 해설, 원문 정제
- 시대, 분야, 목차경로 metadata 생성
- 국문/해설/원문을 섹션 단위로 chunking
- JSONL 출력
```

출력:

```text
historical_sources.documents.jsonl
historical_sources.chunks.jsonl
```

### 4.2 신편 한국사

실행:

```powershell
.\.venv\Scripts\python.exe storage\postgre\scripts\preprocess_new_history.py
```

처리 내용:

```text
- 권별 CSV 파일 로드
- 본문, 각주, 이미지 설명 정제
- 제목의 > 계층을 chapter, section, subsection, topic으로 분리
- 긴 본문을 문단 중심으로 chunking
- JSONL 출력
```

출력:

```text
new_history.documents.jsonl
new_history.chunks.jsonl
```

### 4.3 한국사 이미지 자료

실행:

```powershell
.\.venv\Scripts\python.exe storage\postgre\scripts\preprocess_image_materials.py
```

처리 내용:

```text
- 한국사_이미지_자료.csv 로드
- 제목, 설명, 목록요약 정제
- 키워드의 # 제거 후 리스트화
- 시대, 유형, 분야 metadata 분리
- 로컬 이미지 파일 경로는 저장하지 않고 thumbnail_url, original_image_url 유지
- 이미지 설명 텍스트를 RAG 문서로 변환
- JSONL 출력
```

출력:

```text
image_materials.documents.jsonl
image_materials.chunks.jsonl
```

## 5. 공통 JSONL 구조

### 5.1 documents JSONL

문서 단위 원본 정보를 저장한다.

```json
{
  "doc_id": "hm_056_0010",
  "source_type": "historical_source",
  "source_name": "사료로 본 한국사",
  "original_id": "hm_056_0010",
  "title": "권농 정책",
  "content": "전체 본문",
  "summary": "요약 또는 해설 앞부분",
  "period": "고려 시대",
  "field": "경제",
  "category": "고려 시대 > 경제 > 농업 기술의 발달 > 권농 정책",
  "keywords": ["고려", "권농", "조세", "농업"],
  "source_url": "https://contents.history.go.kr/...",
  "image_path": null,
  "metadata": {}
}
```

### 5.2 chunks JSONL

RAG 검색에 실제로 사용하는 chunk 정보를 저장한다.

```json
{
  "chunk_id": "hm_056_0010_chunk_0000",
  "document_id": "hm_056_0010",
  "source_type": "historical_source",
  "source_name": "사료로 본 한국사",
  "title": "권농 정책",
  "chunk_index": 0,
  "chunk_text": "검색과 임베딩에 사용할 텍스트",
  "token_count": 120,
  "metadata": {
    "period": "고려 시대",
    "field": "경제",
    "category": "고려 시대 > 경제 > 농업 기술의 발달 > 권농 정책",
    "category_tags": ["고려 시대", "경제", "농업 기술의 발달", "권농 정책", "고려", "권농"],
    "chronology": {
      "era": "고려 시대",
      "era_order": 40,
      "dynasty": "고려",
      "start_year": 918,
      "end_year": 1392,
      "period_label": "고려 시대",
      "mentioned_years": [982],
      "primary_year": 982
    },
    "keywords": ["고려", "권농", "조세", "농업"],
    "source_url": "https://contents.history.go.kr/..."
  }
}
```

## 6. Metadata 태깅 기준

하이브리드 RAG에서 필터 검색과 시계열 검색을 강화하기 위해 chunk metadata에 `category_tags`와 `chronology`를 추가한다.

### 6.1 category_tags

`category_tags`는 격 일치와 필터 검색을 위한 정규화 태그 목록이다.

생성에 사용하는 값:

```text
- title
- period
- field
- category
- keywords
- 이미지 자료의 category_main, category_sub
- 신편 한국사의 book_title
```

예시:

```json
"category_tags": [
  "조선 전기",
  "정치",
  "중앙 정치구조",
  "6조 직계제",
  "의정부",
  "육조"
]
```

활용:

```text
- 사용자 질문의 시대/분야/개념과 metadata 필터 매칭
- 키워드 검색 보강
- 동음이의어 완화
- 특정 범위의 자료만 검색할 때 필터 조건으로 사용
```

### 6.2 chronology

`chronology`는 시대 순서 계산과 시계열 필터링을 위한 정규화 metadata이다.

구조:

```json
"chronology": {
  "era": "조선 전기",
  "era_order": 50,
  "dynasty": "조선",
  "start_year": 1392,
  "end_year": 1592,
  "period_label": "조선 전기",
  "mentioned_years": [1392, 1405],
  "primary_year": 1392
}
```

시대 순서 기준:

| era | era_order | 연도 범위 |
|---|---:|---|
| 선사 | 5 | 기원전 700000 ~ 기원전 1500 |
| 삼국 이전 | 10 | 기원전 2333 ~ 300 |
| 삼국 시대 | 20 | 300 ~ 668 |
| 통일 신라와 발해 | 30 | 668 ~ 935 |
| 고려 시대 | 40 | 918 ~ 1392 |
| 조선 전기 | 50 | 1392 ~ 1592 |
| 조선 후기 | 60 | 1592 ~ 1863 |
| 근대 | 70 | 1863 ~ 1945 |
| 현대 | 80 | 1945 ~ |

주의:

```text
- chronology.era는 제목/목차/시대 metadata에 명시된 경우를 우선한다.
- 본문에 특정 시대명이 우연히 등장하는 경우는 오탐이 생길 수 있으므로 era 추정에 보수적으로 접근한다.
- mentioned_years는 본문에 등장한 연도를 추출한 값이므로 참고문헌 연도까지 섞일 수 있다.
- 시계열 정렬의 1차 기준은 era_order, start_year, end_year로 사용한다.
- mentioned_years와 primary_year는 보조 신호로만 사용한다.
```

## 7. Chunking 기준

기본값:

```text
chunk_size: 1200자
chunk_overlap: 150자
```

사료와 신편 한국사는 긴 본문이 많으므로 문단 기준으로 우선 분리하고, 문단이 너무 길면 글자 수 기준으로 나눈다.

이미지 자료는 설명이 짧기 때문에 이미지 하나를 chunk 하나로 처리한다.

옵션 변경 예시:

```powershell
.\.venv\Scripts\python.exe storage\postgre\scripts\preprocess_new_history.py --chunk-size 1000 --chunk-overlap 100
```

## 9. RAG 검색 활용 방식

챗봇은 전처리된 chunk를 기준으로 검색한다.

추천 흐름:

```text
사용자 질문
  ↓
키워드 검색
  - title
  - period
  - field
  - category
  - category_tags
  - chronology.era
  - chronology.dynasty
  - chronology.period_label
  - keywords
  ↓
벡터 검색
  - chunk_text embedding
  ↓
결과 병합
  ↓
source_type 가중치 적용
  ↓
상위 chunk를 LLM에 전달
```

자료별 기본 가중치 예시:

```text
historical_source: 1.2
historical_overview: 1.0
image_material: 0.7
```

이미지 관련 질문인 경우에는 `image_material` 가중치를 높인다.

## 10. PostgreSQL 적재 방향

다음 단계에서는 JSONL 파일을 PostgreSQL에 적재한다.

PostgreSQL과 Neo4j 실행:

```powershell
docker compose -f storage\docker-compose.yml up -d
```

`storage/init.sql`은 PostgreSQL 컨테이너 최초 생성 시 `vector`, `pg_trgm`, `unaccent` 확장과 `rag` 스키마를 만든다.

권장 테이블:

```sql
documents
- id
- source_type
- source_name
- original_id
- title
- content
- summary
- period
- field
- category
- keywords
- source_url
- image_path
- metadata

document_chunks
- id
- document_id
- source_type
- source_name
- title
- chunk_index
- chunk_text
- token_count
- embedding
- metadata
```

`document_chunks.chunk_text`를 임베딩한 뒤 `pgvector` 컬럼에 저장하면 벡터 검색이 가능하다.

## 11. 주의사항

- 원본 CSV는 그대로 보존한다.
- 전처리 결과는 언제든 재생성 가능하므로 원본보다 우선하지 않는다.
- 한국사 이미지 자료는 로컬 저장 이미지 경로 대신 `thumbnail_url`, `original_image_url`, `source_url`을 저장한다.
- 챗봇 답변에서는 이미지 자료보다 사료와 신편 한국사 텍스트 근거를 우선한다.
- 출처 URL과 이용조건 metadata는 삭제하지 않는다.
