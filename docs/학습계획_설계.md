# 학습계획 생성 로직 설계

## 목적

사용자별 학습계획은 단순히 취약한 영역을 나열하는 기능이 아니라, 사용자의 남은 시간 안에서 시험 대비 효율이 높은 학습 순서를 만들어 주는 기능이다.

따라서 학습계획은 다음 정보를 함께 고려한다.

- 하루 학습 가능 시간
- 시험까지 남은 기간
- 취약 시대
- 취약 유형
- 취약 주제
- 평균 풀이시간
- 기출 기반 출제 예상 우선순위

핵심 기준은 다음과 같다.

```text
학습 우선순위 = 개인 취약도 + 출제 예상 중요도 + 시간 부담
```

## 전체 흐름

```text
사용자 학습 정보 조회
-> 개인 취약 항목 생성
-> 기출 기반 출제 예상 항목 조회
-> 취약 항목과 출제 예상 항목 병합
-> 우선순위 점수 계산
-> 남은 기간에 따른 학습 전략 선택
-> 하루 가용시간 기준으로 날짜별 학습 블록 생성
-> 학습계획 저장
```

## 입력 데이터

### 사용자 시간 정보

```python
{
    "daily_available_hours": "float",
    "remaining_days": "int",
}
```

의미:

- `daily_available_hours`: 사용자가 하루에 학습할 수 있는 시간
- `remaining_days`: 시험일까지 남은 날짜 수

### 개인 취약 항목

분석 데이터에서 생성한다.

```python
{
    "classification": "시대 | 유형 | 주제",
    "label": "str",
    "wrong_rate": "float",
    "average_time_sec": "int",
}
```

예시:

```python
{
    "classification": "시대",
    "label": "조선",
    "wrong_rate": 0.42,
    "average_time_sec": 55,
}
```

의미:

- `wrong_rate`: 해당 항목의 오답률
- `average_time_sec`: 해당 항목의 평균 풀이시간

### 출제 예상 항목

기출문제 분석 또는 RAG/예측 로직에서 생성한다.

```python
{
    "classification": "시대 | 유형 | 주제",
    "label": "str",
    "prediction_score": "float",
    "reason": "str",
}
```

예시:

```python
{
    "classification": "주제",
    "label": "정치",
    "prediction_score": 0.91,
    "reason": "최근 기출에서 정치 제도 변화 문제가 반복 출제됨",
}
```

의미:

- `prediction_score`: 출제 예상 중요도
- `reason`: 해당 항목을 중요하게 보는 이유

## 우선순위 계산

학습계획은 취약도만 보지 않는다.

```text
우선순위가 높은 항목 = 사용자가 약하면서 시험에 나올 가능성도 높은 항목
```

기본 점수는 다음 요소로 만든다.

```text
priority_score =
    weakness_score
    + prediction_score
    + time_burden_score
```

### weakness_score

사용자의 오답률을 기반으로 한다.

```text
wrong_rate가 높을수록 weakness_score가 높다.
```

### prediction_score

기출 기반 출제 예상 점수를 사용한다.

```text
출제 예상도가 높을수록 prediction_score가 높다.
```

### time_burden_score

평균 풀이시간을 기반으로 한다.

```text
평균 풀이시간이 길수록 아직 익숙하지 않은 항목으로 본다.
```

단, 평균 풀이시간은 취약도의 보조 지표로만 사용한다.

## 남은 기간별 전략

남은 기간에 따라 우선순위 가중치를 다르게 적용한다.

### 시험까지 7일 이하

```text
목표: 출제 가능성이 높은 취약점 압축 학습
```

특징:

- 출제 예상 중요도 비중을 높인다.
- 취약하지만 출제 가능성이 낮은 항목은 후순위로 둔다.
- 오답 복습 비중을 높인다.

### 시험까지 8일 이상 21일 이하

```text
목표: 취약점 보완과 실전 문제 풀이 병행
```

특징:

- 취약도와 출제 예상 중요도를 비슷하게 본다.
- 시대, 유형, 주제를 섞어서 배치한다.
- 복습 블록을 일정에 포함한다.

### 시험까지 22일 이상

```text
목표: 취약 개념 보완과 반복 복습
```

특징:

- 개인 취약도 비중을 높인다.
- 하루 계획을 너무 압축하지 않는다.
- 1일 후, 3일 후, 7일 후 복습 구조를 넣을 수 있다.

## 우선순위 그룹

학습 대상은 다음 4개 그룹으로 나눌 수 있다.

| 그룹 | 의미 | 처리 |
|---|---|---|
| 취약도 높음 + 출제 예상 높음 | 가장 중요한 학습 대상 | 최우선 배치 |
| 취약도 낮음 + 출제 예상 높음 | 시험에 나올 가능성이 높은 유지 대상 | 짧은 문제풀이 배치 |
| 취약도 높음 + 출제 예상 낮음 | 약하지만 긴급도는 낮은 대상 | 시간이 남을 때 배치 |
| 취약도 낮음 + 출제 예상 낮음 | 우선순위 낮은 대상 | 기본 계획에서는 제외 가능 |

## 하루 학습 시간 배분

하루 가용시간은 다음 블록으로 나눈다.

```text
문제 풀이
해설 확인
오답 정리
복습
```

기본 비율 예시:

```text
문제 풀이: 50%
해설 확인: 25%
오답 정리: 15%
복습: 10%
```

단, 비율은 고정값으로 코드에 박지 말고 설정값으로 관리하는 것이 좋다.

가용시간이 적은 경우:

```text
하루에 너무 많은 항목을 넣지 않는다.
핵심 취약 항목 1개와 짧은 복습 1개 정도로 제한한다.
```

가용시간이 많은 경우:

```text
시대, 유형, 주제를 섞어서 배치한다.
문제 풀이 후 해설과 오답 정리 시간을 반드시 포함한다.
```

## 문제 수 계산

문제 수는 평균 풀이시간을 이용해 계산한다.

```text
문제 1개 예상 시간 = 평균 풀이시간 + 해설/오답 정리 시간
```

예시:

```python
unit_time_sec = average_time_sec + review_time_sec
question_count = allocated_time_sec // unit_time_sec
```

주의:

- 평균 풀이시간만 사용하면 해설과 복습 시간이 빠진다.
- 최소 문제 수와 최대 문제 수 제한이 필요하다.
- 평균 풀이시간이 없으면 기본 예상 시간을 사용한다.

## 날짜별 배치 규칙

### 분산 배치

하루 계획에 같은 분류만 몰아넣지 않는다.

좋은 예:

```text
조선 정치 10문제
사료형 5문제
전날 오답 복습
```

나쁜 예:

```text
조선 30문제
고려 30문제
근대 30문제
```

### 복습 배치

취약도가 높은 항목은 한 번 풀고 끝내지 않는다.

복습 후보:

- 오답률이 높은 항목
- 출제 예상도가 높은 항목
- 평균 풀이시간이 긴 항목

복습 일정 예시:

```text
1차 학습일
-> 1일 후 복습
-> 3일 후 복습
-> 7일 후 복습
```

남은 기간이 짧으면 7일 후 복습은 생략할 수 있다.

## 출력 데이터

학습계획 결과는 날짜별 블록 형태로 만든다.

```python
{
    "study_plan_id": "int",
    "total_days": "int",
    "daily_available_minutes": "int",
    "plans": [
        {
            "date": "date",
            "blocks": [
                {
                    "block_type": "new_weakness | review | prediction_focus",
                    "classification": "시대 | 유형 | 주제",
                    "label": "str",
                    "activity": "str",
                    "question_count": "int",
                    "estimated_minutes": "int",
                    "priority_score": "float",
                    "reason": "str",
                }
            ],
        }
    ],
}
```

예시:

```python
{
    "date": "2026-06-22",
    "blocks": [
        {
            "block_type": "new_weakness",
            "classification": "시대",
            "label": "조선",
            "activity": "조선 시대 취약 문제 풀이 및 해설 정리",
            "question_count": 12,
            "estimated_minutes": 45,
            "priority_score": 0.83,
            "reason": "오답률이 높고 출제 예상도도 높음",
        },
        {
            "block_type": "review",
            "classification": "유형",
            "label": "사료형",
            "activity": "전날 오답 복습",
            "question_count": 5,
            "estimated_minutes": 20,
            "priority_score": 0.71,
            "reason": "반복 오답이 발생한 유형",
        },
    ],

```

## 저장 위치

학습계획은 `study_plan_mypage` 테이블에 저장한다.

현재 모델:

```python
StudyPlanMypage
```

저장 방식:

- `study_plans`: 사용자에게 보여줄 전체 계획 요약
- `study_plan_items`: 날짜별 상세 계획 JSON 문자열
- `created_at`: 생성일
- `modified_at`: 수정일

## 서비스 책임 분리

### analytics service

역할:

- 사용자 풀이 세션 조회
- 취약 시대, 유형, 주제 계산
- 평균 풀이시간 계산
- 학습계획에 넘길 `weak_targets` 생성

### prediction service

역할:

- 기출 기반 출제 예상 항목 생성
- 시대, 유형, 주제별 `prediction_score` 제공
- 출제 예상 이유 제공

### studyplan service

역할:

- 사용자 시간 정보 조회
- 취약 항목과 출제 예상 항목 병합
- 우선순위 계산
- 날짜별 학습 블록 생성
- `StudyPlanMypage` 저장

## 구현 시 주의사항

- 출제 예상 데이터가 없으면 개인 취약도만으로 계획을 생성한다.
- 평균 풀이시간이 없으면 기본 문제 풀이 시간을 사용한다.
- 남은 기간이 0일 이하이면 당일 압축 계획만 생성한다.
- 하루 가용시간이 너무 적으면 문제 수를 무리하게 늘리지 않는다.
- 취약 항목이 없으면 출제 예상도가 높은 항목 중심으로 유지 학습 계획을 만든다.
- 설정값은 코드 내부에 하드코딩하지 않고 별도 상수 또는 설정 객체로 관리한다.
