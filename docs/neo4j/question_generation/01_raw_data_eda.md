# 01. 문제 생성용 raw 데이터 EDA

> 목적: 원천 파일을 Neo4j에 바로 넣는 것이 아니라, 어떤 필드를 엔터티·관계·근거로 사용할 수 있는지 판단한다.
> 방식: 2026-07-15 기준 전체 행을 UTF-8로 스트리밍 집계했다. 표본 행만 보고 추정하지 않았다.

CSV 셀 안에 CRLF가 포함된 파일이 있으므로 물리 줄 수가 아니라 표준 CSV parser가 읽은 논리 행 수를 사용했다. JSONL 파싱 오류와 CSV 열 개수 오류는 모두 0건이었다.

## 1. 분석 대상

## 2. 결론부터 요약

| 원천 | 가장 강한 역할 | 그대로 사용하면 위험한 부분 |
|---|---|---|
| 대백과사전 상세 | 정답·오답 RAG 본문, 원천 표제어, 별칭, 시대, 유형, 구조화 속성 | 관련 문서 링크 290,669건은 관계 의미가 없으므로 정답 관계로 사용 불가 |
| 고전종합DB 인물 관계 | 가족·사제·교유처럼 관계명이 명확한 인물 그래프 | 동명이인이 많고 일부 중복 행이 있어 ID 기준 정규화 필요 |
| 고전종합DB 사건 관계 | 고려·조선 사건과 연관 인물 후보 | 관계 유형이 전부 `사건인물`이고 근거 URL이 비어 있어 추가 근거 검증 필요 |
| 역사용어시소러스 | 시대, 분류 경로, 한자명, 짧은 정의, 용어 ID | 같은 이름의 서로 다른 용어가 많아 이름만으로 병합 불가 |

현재 원천은 `분류상 비슷한 후보`를 찾는 데는 충분하지만, 모든 시험형 문항에 필요한 `인물-업적`, `사건-결과`, `조약-조항` 같은 관계가 완성되어 있지는 않다. 대백과사전의 구조화 속성과 본문에서 `FactCandidate`를 추출하고 RAG 근거로 검증하는 단계가 필수다.

## 3. 한국민족문화대백과사전 EDA

### 3.1 행과 키

| 지표 | `articles_list.jsonl` | `articles_detail.jsonl` |
|---|---:|---:|
| 전체 행 | 75,935 | 75,835 |
| 고유 `eid` | 75,835 | 75,835 |
| 중복 `eid` 행 | 100 | 0 |
| JSON 파싱 오류 | 0 | 0 |
| 상세 본문 존재 | 0 | 75,820 |

목록 파일의 75,835개 고유 ID는 상세 파일과 모두 일치한다. 따라서 다음 기준을 사용한다.

- `articles_detail.jsonl`을 본문과 메타데이터의 기준 원천으로 사용한다.
- `articles_list.jsonl`은 수집 누락 비교, 원천 감사, 상세에 없는 유효 `headMedia` 보강에만 사용한다.
- 목록 파일의 중복 100행을 canonical entity로 중복 생성하지 않는다.
- 상세에 없는 유효 `headMedia`는 목록 파일에서 보강하되, 병합 규칙과 출처를 기록한다.

### 3.2 본문과 구조화 필드

| 항목 | 결과 | 사용처 |
|---|---:|---|
| `body` 존재 문서 | 75,820 | RAG 청크 원문 |
| 본문 길이 중앙값 | 866자 | 청크 전략 기준 |
| 본문 길이 95백분위 | 3,298자 | 긴 문서 분할 기준 |
| 본문 최대 길이 | 177,833자 | 이상치·대형 문서 별도 분할 |
| 별칭 보유 문서 | 24,435 | 엔터티 검색 및 해소 |
| 별칭 항목 | 45,293 | `NameVariant` 후보 |
| 구조화 속성 항목 | 237,787 | 시간·장소·저자 등 `FactCandidate` |
| 해시태그 | 174,191 | 검색 태그, 정답 관계로는 사용 금지 |
| 관련 문서 링크 | 290,669 | 후보 근접성 또는 추가 추출 큐 |
| 내부 ID로 해소되는 관련 링크 | 290,301 | 출처 레코드 간 탐색 |
| 관련 미디어 | 57,711 | 이미지 메타데이터와 권리 확인 |

`articleAttributes`는 `groupName`, `attrName`, `attrValue` 구조다. 많이 등장하는 속성에는 출생 연도, 사망 연도, 소재지, 본관, 주요 관직, 관련 사건, 제작 시기, 저자, 관련 인물, 관련 국가, 설립 시기 등이 있다.

`era`는 단일 값만 있는 필드가 아니다. 상세 기준 14,900건은 시대 2개, 247건은 3개 이상을 ` | `로 포함한다. `field`도 2개 이상이 결합된 행이 2,549건이므로 문자열 전체를 하나의 Era 또는 Category로 만들지 않는다.

속성은 다음처럼 나눈다.

- 결정론적으로 파싱 가능한 값: 출생·사망 연도, 좌표, 지정일, 제작·설립·폐지 시기
- 엔터티 해소가 필요한 관계 값: 저자, 관련 인물, 관련 사건, 관련 국가, 소재지
- 검색 보조 값: 해시태그, 분류, 요약
- 직접 정답 관계로 금지할 값: 의미가 불명확한 `relatedArticles`

`relatedArticles`는 두 문서가 관련 있다는 사실만 제공하며 `CREATED`, `CAUSED_BY`, `PARTICIPATED_IN` 같은 술어를 제공하지 않는다. 따라서 다음처럼 적재한다.

```text
(AKSArticle)-[:HAS_RELATED_SOURCE_RECORD {answer_eligible:false}]->(AKSArticle)
```

이 관계는 관계 추출 대상의 우선순위를 높이는 데만 사용하고, 오답 후보의 참·거짓 판정에는 사용하지 않는다.

관련 문서 290,669건 중 290,301건은 현재 상세 EID로 해소되고, 368건은 현재 문서 집합에 없는 120개 EID를 가리킨다. 미해소 endpoint를 임의 이름 노드로 생성하지 않고 검토 큐에 격리한다.

### 3.3 대백과사전의 Neo4j/RAG 분리

| 필드 | Neo4j | RAG |
|---|---|---|
| `eid`, `headword`, `origin`, `articleAliases` | 출처 레코드와 이름 변형 | 검색 메타데이터 |
| `primaryType`, `field`, `era` | 타입·분류·시대 후보 | 필터 메타데이터 |
| `articleAttributes` | 파싱 후 `FactCandidate` | 해당 사실의 원문 보강 |
| `definition`, `summary`, `body`, `reference` | 전체 저장 금지, 청크 ID만 연결 | 본문 청크와 임베딩 |
| `relatedArticles` | 비의미적 출처 링크 | 연관 문서 검색 보조 |
| `headMedia`, `relatedMedias` | URL·해시·권리·캡션 참조 | 이미지 검색 메타데이터 |

`person_id`를 출처 레코드의 키로 사용한다. 이름은 키가 아니다. 이름, 한자, 생몰년, 본관, 자, 호, 부친, 관계 이웃을 함께 사용해 다른 원천의 인물과 해소한다.

`ja`와 `ho`에는 쉼표로 구분된 다값이 있고, 생몰년에는 `15??`, `B.C.58`, `1745(1730)`, `1876/1877` 같은 표현이 있다. 원문을 보존하고 값별 NameVariant 및 불확실 TimeSpan으로 파싱한다.

관계 유형은 16종이다.

```text
부, 생부, 모, 생모, 자, 조부, 증조부, 형제,
아내, 남편, 장인, 사위, 교유, 스승, 제자, 출자
```

관계 방향과 역관계를 사전에 정의해야 한다. 예를 들어 `스승`과 `제자`, `부`와 `자`는 서로 다른 방향이며, `형제`와 `교유`는 대칭 관계다. 원문 문자열을 그대로 Neo4j 관계 타입으로 만들지 않고 승인된 `Predicate` 사전에 매핑한다.

### 4.3 사건

| 지표 | 값 |
|---|---:|
| `itkc_events.csv` 전체 행 | 1,542 |
| 고유 `event_id` | 600 |
| 중복 범위 행 | 942 |
| 고려 사건 | 267 |
| 조선 사건 | 333 |
| 사건 날짜 존재 | 595 |
| 관련 사건 문자열 존재 | 224 |

같은 사건이 `event_subject`, `event_period` 범위로 반복 수집되어 있다. `event_id` 기준으로 한 번만 canonical staging 행을 만들고, 여러 상세 URL은 출처 URL 목록으로 합친다.

`related_event`에는 32종의 집단 사건명이 있으나 현재 600개 사건의 `event_name`과 정확히 일치하지 않는다. 곧바로 Event endpoint로 만들지 않고 `UnresolvedMention` 또는 검토 후보로 둔다.

사건 데이터의 범위는 고려와 조선에 한정되어 있다. 선사, 삼국, 남북국, 근대, 일제강점기, 현대 문항까지 이 원천만으로 생성할 수 있다고 가정하면 안 된다.

### 4.4 사건-인물 관계

| 지표 | 값 |
|---|---:|
| 전체 행 | 15,392 |
| scope·중복 제거 후 사건-인물 edge | 6,918 |
| 관계 유형 | `사건인물` 1종 |
| 출발 사건 ID 미해소 | 0 |
| 도착 인물 ID 미해소 | 0 |
| 동일 사건·인물 키 중복 행 | 8,474 |

중복 대부분은 동일 관계가 두 수집 범위에 반복된 결과다. `event_id + person_id`로 정규화하되 여러 URL을 보존한다.

`사건인물`은 참여, 지휘, 피해, 명령, 기록 등 구체적인 역할을 알려 주지 않는다. 그러므로 초기에는 다음처럼 낮은 의미 수준의 후보로만 사용한다.

```text
FactCandidate
  predicate = ASSOCIATED_WITH_EVENT
  agent = Person
  event = Event
  status = NEEDS_ROLE_ENRICHMENT
  answer_eligible = false
```

RAG 본문에서 실제 역할을 확인해 `PARTICIPATED_IN`, `COMMANDED`, `LED`, `ORDERED` 등으로 승격된 사실만 문제 생성 경로에 사용한다.

## 5. 한국역사용어시소러스 EDA

| 지표 | 값 |
|---|---:|
| 전체 행 | 62,409 |
| 고유 `term_id` | 62,409 |
| `term_kind=2` 실제 용어 | 61,598 |
| `term_kind=1` 분류·색인 후보 | 794 |
| `term_kind=0` 최상위 분류 | 17 |
| null sentinel과 공백 정규화 후 설명 존재 | 61,278 |
| `strip()` 후 연도 표현 존재 | 60,995 |
| 시대 표현 존재 | 60,543 |
| `term_lk` 다중 경로 `>>` 포함 | 98 |
| 같은 `term_name`을 공유하는 이름 그룹 | 3,944 |
| 해당 중복 이름 그룹에 속한 행 | 9,658 |

### 5.1 필드 해석

- `term_id`: 유일하므로 출처 레코드 ID로 사용한다.
- `term_name`: 검색 이름이며 canonical ID가 아니다.
- `term_ch`: 한자·원문 이름 변형으로 사용한다.
- `topterm_id`: 직접 부모가 아니라 17개 최상위 분류 코드다.
- `term_lk`: `>`가 계층 구분자이고 `>>`가 복수 분류 경로 구분자다.
- `term_year`: `?`, 범위, 복수 연도 등이 섞인 원문 시간 표현이다.
- `term_times`: 시대 필터의 강한 후보지만 정규화가 필요하다.
- `term_desc`: 짧은 정의와 RAG 검색 보조로 사용한다.

빈 문자열 외에 공백 문자열과 `_NULL_` sentinel이 섞여 있으므로 `strip()` 후 null을 통일한다. `term_year`에는 단일 연도, 범위, `?`, 복수 구간, `B.C.57-A.D.935`, `1948-`, `1920년대`가 섞여 있어 단순 문자열 분할로 처리하지 않는다.

`topterm_id`를 용어 간 부모 관계로 해석하지 않는다. `term_lk`를 분해해 별도의 `Category` 계층을 만들고 용어를 leaf category에 연결한다.

```text
정치·행정·법제>정치>정치조직·단체

(Term)-[:HAS_CATEGORY]->(정치조직·단체)
(정치조직·단체)-[:SUBCATEGORY_OF]->(정치)
(정치)-[:SUBCATEGORY_OF]->(정치·행정·법제)
```

## 6. 교차 원천 이름 매칭 EDA

다음 표는 `NFKC → 앞뒤 공백 제거 → 괄호 안 한자 분리 → 공백·구두점 제거` 순서의 한글 이름 키로 비교한 결과다. 사용 필드는 대백과사전의 `headword`와 `articleAliases`, 시소러스의 `term_name`, 고전종합DB 인물 원천의 `name`을 staging에서 바꾼 `person_name`, 또는 canonical `event_name`이다. `subject_category`, `related_event`처럼 엔터티 이름이 아닌 필드는 제외했다. 집계 단위는 원시 행이 아니라 고유 정규화 이름 키이며, 1대1은 그 키가 양쪽에서 각각 하나의 고유 출처 레코드만 가리키는 경우다.

이는 자동 병합 결과가 아니라 이름 기반 후보 규모를 측정한 것이다. 정규화 규칙은 `name-normalization-eda-v1`로 버전 관리하고, 규칙이나 사용 필드가 바뀌면 표 전체를 다시 산출한다.

| 원천 쌍 | 공유 정규화 이름 | 1대1 고유 이름 | 한쪽 이상 다의적인 이름 |
|---|---:|---:|---:|
| 대백과사전 ↔ 시소러스 | 33,002 | 26,985 | 6,017 |
| 대백과사전 ↔ 고전종합DB 인물 | 10,126 | 5,328 | 4,798 |
| 대백과사전 ↔ 고전종합DB 사건 | 32 | 31 | 1 |
| 시소러스 ↔ 고전종합DB 인물 | 5,297 | 2,980 | 2,317 |
| 시소러스 ↔ 고전종합DB 사건 | 36 | 35 | 1 |

동명이인과 동음이의어 비율이 높다. `태조`, 짧은 관직명, 한 글자 용어처럼 이름이 같아도 다른 엔터티가 많으므로 다음 규칙이 필요하다.

- 이름 일치만으로 `SAME_AS`를 만들지 않는다.
- 이름, 한자, 엔터티 타입, 시대 교집합, 생몰년, 본관, 장소, 관계 이웃을 종합한다.
- 자동 임계값은 코드에 넣지 않고 버전 있는 `EntityResolutionPolicy` 데이터로 관리한다.
- 불확실한 매칭은 `CANDIDATE_SAME_AS`로 두고 문제 생성 대상에서 제외한다.

## 7. 원천별 최종 사용 판정

| 원천 데이터 | 적재 대상 | 생성 사용 조건 |
|---|---|---|
| 대백과사전 표제어·별칭·타입·시대 | `SourceRecord`, `NameVariant`, 타입·시대 후보 | 엔터티 해소 완료 |
| 대백과사전 구조화 속성 | `FactCandidate` | 파싱·대상 해소·RAG 근거 검증 후 `ACCEPTED` |
| 대백과사전 관련 문서 | 출처 간 비의미적 링크 | 정답·오답 판정 금지 |
| 대백과사전 본문 | RAG 청크 | 출처와 청크 ID가 Fact에 연결되어야 함 |
| 고전종합DB 인물 관계 | typed `FactCandidate` | 방향·중복·출처 검증 후 사용 |
| 고전종합DB 사건-인물 | 낮은 수준의 관계 후보 | 구체 역할과 근거를 보강한 뒤 사용 |
| 시소러스 분류·시대 | `Category`, `Era`, `TimeSpan` 후보 | 파싱 상태가 승인된 행만 사용 |
| 시소러스 설명 | RAG 보조 청크 또는 짧은 정의 | 본문 근거의 단독 대체물로 쓰지 않음 |

## 8. EDA 단계 품질 게이트

ETL을 시작하기 전에 매 실행에서 다음을 자동 검증한다.

1. 파일 해시와 스키마가 등록된 버전과 일치한다.
2. JSON/CSV 파싱 실패율이 허용 정책 이하다.
3. 출처 기본키 중복이 정규화 규칙으로 설명된다.
4. 관계의 출발·도착 ID가 원천 엔터티에 존재한다.
5. 새로운 관계 유형·분류 루트·속성명이 발견되면 자동 승인하지 않는다.
6. 이름만으로 병합된 canonical entity가 없다.
7. 시간 파싱 실패와 모호한 범위는 검토 큐에 남는다.
8. `answer_eligible=true`인 Fact에는 승인 근거가 최소 하나 있다.
9. RAG 청크 ID가 실제 검색 저장소에 존재한다.
10. 생성용 PathInstance는 `ACCEPTED` Fact만 참조한다.
