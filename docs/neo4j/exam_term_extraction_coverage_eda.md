# 기출문제 용어 추출·커버리지 EDA

> 문서 상태: `EVIDENCE-SNAPSHOT`
> 기준일: 2026-07-20 (같은 날 갱신: 이름 매칭·definition 스캔·오탐 대응 추가)
> 대상 코드: `etl/preprocessing/neo4j/terms/get_history_terms.py`, `prep_thesaurus.py`,
> `match_names.py`, `scan_definitions.py`, `run_neo4j_preprocessing.py`
> 용도: LLM 용어 추출 프롬프트와 시소러스·백과사전·ITKC 매칭 로직의 개선 근거 보존

기출문제 JSON에서 핵심 역사 용어를 추출하고, 한국역사용어시소러스와
한국민족문화대백과사전에 매칭해 Neo4j `SourceRecord`·`EntityName` 기반을 만드는
과정에서 수행한 EDA와 그에 따른 개선 이력을 정리한다.

## 1. 추출 프롬프트 개선 이력

### v1 → v2: 핵심 판정 기준·제외 대상 도입

v1 프롬프트는 추출 규칙과 필드 규칙만 있었다. v2에서 다음을 추가했다.

- 핵심 판정 기준: 교과서 색인·백과사전 표제어로 실릴 수 있는 개념만 용어로 인정.
  확신이 없으면 추출하지 않음(정밀도 우선)
- 제외 대상 명시: 자리 표시 기호("(가) 정부" 포함), 일반 명사, 역사적 의미 없는
  일반 사물(수달가죽, 노둣돌), 서술이 붙은 파생 표현(고종 즉위 → 고종),
  일반적 지칭(일본인 재정 고문), 연도·조항 번호, 성씨 단독 표현
- 추출 예시를 선사시대·근현대사 2개로 확장

### v2 전체 실행 결과 EDA (4,678개 고유 용어)

- count=1 용어가 55%(2,584개)였으나 샘플링 결과 대부분 정상적인 희귀 출제 용어
  (훙커우 공원 의거, 다루가치, 원종과 애노의 난 등). 기출 데이터 특성상 자연스러운 분포
- 실제 문제는 카테고리였다. 허용 목록(15종) 밖 값이 97건 발생:
  법령, 연호, 관직, 화폐, 정부, 군사제도 등. LLM 오류라기보다 카테고리 목록에
  해당 개념을 넣을 칸이 없었던 것이 원인

### v2 카테고리 오분류 패턴

| 패턴 | 사례 | 올바른 분류 |
|---|---|---|
| 군사 조직 → 단체 | 별무반, 삼별초, 한국광복군 | 기관 |
| 법령 → 정책 | 회사령, 치안 유지법 | 제도 |
| 연호 → 정책 | 건양 | 제도 |
| 외국 국명 → 왕조 | 송, 명 | 국가 |
| 왕조에 잡동사니 | 보덕왕(인물), 부여씨(성씨), 조선 후기(시대) | — |
| 신문 → 기관 | 대한매일신보 | 문헌 |
| 제천 행사 → 사상 | 영고, 무천, 동맹 | 제도 |
| 일반어 혼입 | '조약', 'FTA', '불상', '담배' | 제외 대상 |
| canonical 중복 | 활구/은병 별도 집계 | 이칭 통일 필요 |

### v2 → v3: 카테고리 분류 규칙 신설

- 15개 카테고리별 1줄 정의와 경계 규칙을 프롬프트에 추가
  (법령·관직·연호·제천 행사 → 제도, 군사 조직 → 기관, 신문 → 문헌,
  화폐 → 유물, 외국 국명 → 국가)
- 제외 대상 강화: 수량 표현, 간지·연도 지칭(을미, 계사년), 종류 상위 일반어
- canonical_term 이칭 통일 규칙 추가 (활구 → 은병)

### v3 소량 테스트 결과 (40문항, 345개 용어)

- 허용 목록 밖 카테고리 0건 (v2: 97건)
- 경계 규칙 적용 확인: 광무·건양·인안 → 제도, 교수·훈도 → 제도,
  별무반·별기군 → 기관, 은병 → 유물, 당·명·금 → 국가
- 잔여 노이즈 약 2% (불상, 신문, 조서 등 일반어 슬립, 연맹 왕국 등 경계 애매).
  프롬프트만으로 더 조이기 어려운 수준으로 판단하고 이후 단계(매칭·검증)에서 처리

### v3 이후 추가 수정: 작물·음식 제외 (고구마·감자 오분류)

v3 전체 실행 결과에서 '고구마', '감자'가 category 유물로 추출된 것을 발견했다.
원인은 유물 정의 문구의 "출토·전래된 물건"이었다. 기출 지문에서 고구마·감자가
항상 '전래'와 함께 나오니 LLM이 "전래된 물건 = 유물"로 문자 그대로 적용한 것이다.

- 유물 정의를 "발굴·출토된 옛 물건과 기물"로 수정 ('전래' 삭제)
- 제외 대상에 작물·음식·상품 항목 추가 (고구마, 감자, 담배, 인삼).
  전래·재배가 시험에 나와도 사물 자체는 제외하고 '구황 작물' 같은 개념어만 추출
- 프롬프트만 수정해 두고 재추출(API 재호출)은 하지 않음. 기존 CSV의 해당 용어는
  후속 판별 단계에서 거르거나 수동 제거

## 2. 시소러스·백과사전 커버리지 EDA

### v3 전체 실행 결과 (4,771개 고유 용어 기준)

| 구분 | 개수 | 비고 |
|---|---|---|
| 시소러스 정확 일치 | 2,804 | 정규화 키 기준 |
| 시소러스 부분 일치 | 126 | 접두어 + 꼬리 3글자 이하 |
| 백과사전 2차 매칭 | 344 | headword + articleAliases |
| 미커버 | 1,497 | 커버리지 68.6% |

백과사전 2차 매칭은 시소러스에서 못 찾은 용어만 대상으로 하며,
`articles_detail.jsonl`의 `headword`와 `articleAliases`를 정규화 키로 대조한다.

### 미커버 1,497개의 성격 분석

미커버 용어는 세 부류로 나뉘며 각각 대응이 다르다.

1. **표기 변형** (가장 많음) — 매칭 로직 개선으로 구제 가능
   - 두음법칙: 류성룡 ↔ 유성룡
   - 숫자 표기: 십이목 ↔ 12목, 16관등제 ↔ 십육관등제
   - 표제어 접두 수식: 경천사지 십층석탑 ↔ 개성 경천사지 십층석탑
   - 칭호 차이: 눌지왕 ↔ 눌지마립간 (단순 포함 매칭으로는 불가)
   - 중간 축약: 6·15 공동 선언 ↔ 6·15남북공동선언 (포함 매칭으로는 불가)
2. **추출 노이즈** — 집계에서 제외해야 함
   - 문장형: '도둑질한 자에게 12배로 배상하게 하였다'
   - 한 글자 일반어: '왕', '난', '철'
3. **백과사전 미등재 용어** — 본문에는 언급되지만 표제어가 없는 경우
   - 본문 검색으로 찾은 문서는 해당 용어를 "설명"하지 않으므로
     설명 소스가 아니라 관계·근거(MENTIONED_IN, EvidenceSpan) 용도로만 사용해야 함

## 3. 매칭 로직 개선 사항 (`prep_thesaurus.py`)

위 분석의 1·2번 부류에 대한 대응으로 반영했다.

- `build_match_key`
  - 1~2자리 숫자를 한자어 독음으로 통일 (12목 == 십이목).
    세 자리 이상(1392, 6·15의 615)은 그대로 두어 연도 오변환 방지
  - 첫 글자 ㄹ 초성에 두음법칙 적용 (류성룡 == 유성룡).
    ㅣ·y계 모음 앞은 ㅇ, 그 외는 ㄴ으로 변환
- `find_affix_matches` (기존 접두어 매칭 확장)
  - 접두 매칭: 추출어가 표제어의 접두어이고 꼬리 3글자 이하 (운요호 → 운요호사건)
  - 접미 매칭 추가: 추출어가 표제어의 접미어이고 머리 3글자 이하
    (경천사지십층석탑 → 개성경천사지십층석탑)
  - 2글자 이하 용어는 오탐 방지를 위해 제외 유지 (남성 → 남성록 방지)
  - 시소러스·백과사전 양쪽 매칭에 동일 적용
- `is_noise_term`
  - 문장형(공백 2개 이상 + 서술형 어미로 종결)과 한 글자 용어를 커버리지 집계에서
    제외하고 리포트 `noise_filtered_terms`에 별도 기록
  - '금융실명거래 및 비밀보장에 관한 긴급재정경제명령' 같은 긴 법령명이
    걸리지 않는 것을 확인함 (공백 개수만으로 판정하지 않는 이유)
- `load_encyclopedia_terms` / `--encyclopedia-jsonl`
  - 백과사전 headword·articleAliases를 `{정규화 키: 표제어}` 사전으로 로드해
    시소러스 미커버 용어의 2차 매칭에 사용
  - `run_neo4j_preprocessing.py`는 경로 미지정 시
    `etl/raw_data/한국민족문화대백과사전/articles_detail.jsonl`이 있으면 자동 사용

개선 반영 후 전체 커버리지 수치는 파이프라인 재실행 후 이 문서에 갱신한다.

## 4. 이름 매칭·definition 스캔 단계 (`match_names.py`, `scan_definitions.py`)

설명(SourceRecord)·관계 추출로 가기 위한 전 단계로, 전체 용어를 문서·ID에
연결하는 파이프라인을 추가했다. `run_neo4j_preprocessing.py`의 [4/5]·[5/5] 단계로
통합되어 있다.

### 설계 원칙

- 후보를 확정하지 않고 전부 기록한다. 규칙·플래그는 "표시"만 하고,
  확정(동명이인·다의어 판별)은 후속 LLM 판별 단계에서 수행한다.
- 노이즈도 제거하지 않고 `is_noise` 플래그로만 표시한다 (매칭률 집계에서만 분리).

### 이름 매칭 (`match_names.py` → `term_name_matches.json`)

전체 용어를 세 소스와 이름 매칭한다.

| 소스 | 매칭 방식 | 비고 |
|---|---|---|
| 백과사전 headword·articleAliases | 정확 + 접두·접미 | 동일 headword 복수 문서는 후보로 전부 기록 |
| ITKC 사건명 (2,345건) | 정확 + 접두·접미 | 사건 계층(related_event)은 관계 단계에서 활용 |
| ITKC 인물명 (65,539명) | 정확 일치만 | '김구' → '김구해' 오매칭 방지. '가일(可逸)' 형식은 한글/한자 분리 |

ITKC 매칭은 커버리지를 올리지 못한다(백과사전과 표제어가 거의 겹침).
ITKC의 가치는 인물 관계 21만 건·생몰년(동명이인 판별 보조)·사건 계층이
공짜로 붙는 것이다.

### definition 스캔 (`scan_definitions.py` → `definition_scan_matches.json`)

이름 매칭에 전부 실패한 용어를 백과사전 definition 문장에서 찾는다
('16관등제'처럼 표제어는 없지만 definition에 언급되는 경우).
용어 키를 하나의 정규식으로 묶어 전체 definition을 한 번만 스캔한다 (LLM 비용 0).
본문(body) 전체 검색은 하지 않는다 — 언급 문서는 용어를 "설명"하지 않으므로,
본문 활용은 관계·근거(MENTIONED_IN, EvidenceSpan) 용도로만 남겨둔다.

### 발견한 오탐 패턴과 대응 (의심 플래그)

| 패턴 | 사례 | 대응 |
|---|---|---|
| 지명 접미 부분 일치 | '광혜원'(제중원 옛 이름)이 "진천군 광혜원면"의 묘소 문서에 매칭 | 용어 뒤에 면·리·군·읍·동·촌이 붙으면 `suspect_place_suffix` 플래그 + 원문 문맥(`context`) 저장 |
| 의미 불일치 (동명이물) | 기관인 '광혜원'이 유적 문서에 매칭 | 추출 category ↔ 백과 `primaryType` 대분류 대응표로 `category_mismatch` 플래그 |

category-primaryType 대응표는 우리 15개 카테고리 각각에 호환되는 AKS 대분류
(인물·문헌·유적·개념·제도·작품·단체·지명·물품·사건·의례·행사 등) 집합을 정의한 것이다.
대응표에 없는 category나 primaryType 미지정 문서는 판단 불가로 보고 호환 처리한다.
플래그 붙은 후보는 정렬에서 뒤로 밀리고, 후보 전부가 플래그면 리포트에
"오탐 가능성 높음"으로 집계된다.

## 5. 남은 과제

- LLM 판별 단계: 용어 + 기출 문항 문맥 + 후보 definition·context·의심 플래그를 주고
  문서 1개를 확정 (동명이인·다의어·오탐 후보를 여기서 최종 정리).
  ITKC 생몰년을 판별 보조 신호로 함께 입력
- 설명·관계 추출 단계: 확정 문서의 body로 요약과 관계를 **한 콜에** 추출해
  입력 토큰 절약. 관계 상대는 canonical 용어 집합으로 사후 필터링,
  근거 문장은 EvidenceSpan으로 저장. 시소러스로만 확정된 용어도 관계 추출에는
  백과 문서가 필요하므로 이 매칭 결과를 그대로 사용
- ITKC 관계 CSV(인물-인물 21만 건, 사건-인물 1.6만 건)를 RelationCandidate로 변환
  (LLM 불필요, evidence_url 보존)
- 포함 매칭으로 못 잡는 변형: 칭호 차이(눌지왕/눌지마립간), 중간 축약(6·15 공동 선언).
  후보 수집(유사도·임베딩) 후 LLM 판별로 넘기는 것이 안전
- 백과사전 미등재 용어: 본문 언급 문서를 MENTIONED_IN + EvidenceSpan으로 연결하거나,
  언급 문장 기반 LLM 요약 설명(unverified 표시), 또는 설명 없는 엔티티로 유지
- 매칭 확정 결과의 스키마 반영: 유일 매칭 → `EntityName -REFERS_TO-> CanonicalEntity`,
  백과사전 문서 → `SourceRecord`, 매칭 근거 → `EvidenceSpan`
- 재실행 후 수치 갱신: 개선된 매칭·이름 매칭·definition 스캔의 실측 결과를
  2절·4절에 반영
