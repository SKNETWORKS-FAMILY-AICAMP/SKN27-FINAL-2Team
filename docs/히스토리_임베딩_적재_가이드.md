# 히스토리 임베딩 적재 가이드

## 1. 위치

임베딩 ETL 파일은 아래 폴더에 둔다.

```text
etl/history/embedding/
  embed_chunks_to_pgvector.py
  evaluate_golden_questions.py
  golden_questions.jsonl
  eval_results.csv
  eval_results.json
```

기본 입력 데이터는 전처리 결과 JSONL이다.

```text
etl/preprocessing/history/processed/
  historical_sources.chunks.jsonl
  new_history.chunks.jsonl
  image_materials.chunks.jsonl
```

## 2. 사전 준비

프로젝트 루트에 `.env`를 만든다.

```env
OPENAI_API_KEY=your_openai_api_key
EMBEDDING_MODEL=text-embedding-3-small
EMBEDDING_DIMENSIONS=1536

POSTGRES_DB=history_rag
POSTGRES_USER=himate
POSTGRES_PASSWORD=himate1234
POSTGRES_PORT=5432
```

PostgreSQL과 Neo4j를 실행한다.

```powershell
docker compose -f storage\docker-compose.yml up -d
```

## 3. 테스트 적재

처음에는 10개만 임베딩해서 연결을 확인한다.

```powershell
.\.venv\Scripts\python.exe etl\history\embedding\embed_chunks_to_pgvector.py --limit 10
```

정상 출력 예시:

```text
upserted_chunks=34706
embedded_chunks=10 batch_size=10
done
```

`upserted_chunks`는 JSONL chunk를 PostgreSQL에 저장한 수이고, `embedded_chunks`는 이번 실행에서 임베딩한 수이다.

## 4. 전체 임베딩 적재

전체 chunk를 임베딩한다.

```powershell
.\.venv\Scripts\python.exe etl\preprocessing\history\embedding\embed_chunks_to_pgvector.py --limit 40000 --batch-size 20 --sleep 2 --create-index
```

OpenAI rate limit이 발생하면 스크립트가 자동으로 기다린 뒤 배치 크기를 줄여 이어서 처리한다.

중간에 끊겨도 다시 같은 명령을 실행하면 `embedding IS NULL`인 chunk부터 이어서 처리한다.

## 5. 특정 파일만 적재

이미지 자료 metadata만 다시 upsert하려면 아래처럼 실행한다.

```powershell
.\.venv\Scripts\python.exe etl\history\embedding\embed_chunks_to_pgvector.py --chunk-file image_materials.chunks.jsonl --limit 0
```

신편 한국사만 다시 upsert하려면:

```powershell
.\.venv\Scripts\python.exe etl\history\embedding\embed_chunks_to_pgvector.py --chunk-file new_history.chunks.jsonl --limit 0
```

`--limit 0`은 임베딩을 새로 만들지 않고 JSONL 내용만 DB에 upsert한다.

## 6. DBeaver 확인 쿼리

전체 chunk 수:

```sql
SELECT COUNT(*)
FROM rag.document_chunks;
```

임베딩 완료 수:

```sql
SELECT COUNT(*)
FROM rag.document_chunks
WHERE embedding IS NOT NULL;
```

이미지 URL 확인:

```sql
SELECT
  title,
  metadata->>'thumbnail_url' AS thumbnail_url,
  metadata->>'original_image_url' AS original_image_url,
  metadata->>'source_url' AS source_url
FROM rag.document_chunks
WHERE source_type = 'image_material'
LIMIT 10;
```

## 7. 벡터 인덱스 확인

인덱스 목록:

```sql
SELECT indexname
FROM pg_indexes
WHERE schemaname = 'rag'
  AND tablename = 'document_chunks';
```

아래 인덱스가 있으면 벡터 검색 인덱스가 생성된 것이다.

```text
document_chunks_embedding_cosine_idx
```

메모리 부족으로 인덱스 생성이 실패하면 DBeaver에서 아래 SQL을 실행한다.

```sql
SET maintenance_work_mem = '128MB';

CREATE INDEX IF NOT EXISTS document_chunks_embedding_cosine_idx
ON rag.document_chunks
USING ivfflat (embedding vector_cosine_ops)
WITH (lists = 100)
WHERE embedding IS NOT NULL;

ANALYZE rag.document_chunks;
```
