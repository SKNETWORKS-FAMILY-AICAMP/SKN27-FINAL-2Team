# 공통 결과 페이지 개발 참고

## 현재 공통화된 부분

- 문제풀이 풀이 페이지(`/question/exam/`)와 진단평가 풀이 페이지(`/diagnosis/exam/`)는 공통 템플릿 `app/templates/question/question_exam.html`을 사용합니다.
- 문제풀이 결과 페이지(`/question/result/`)와 진단평가 결과 페이지(`/diagnosis/result/`)는 공통 템플릿 `app/templates/study/result.html`을 사용합니다.
- 풀이 템플릿은 `exam_mode`, 결과 템플릿은 `result_mode` 값으로 문제풀이(`practice`)와 진단평가(`diagnostic`) 화면 문구와 데이터 로딩 방식을 구분합니다.
- 결과 페이지의 노트 저장 버튼은 `POST /question/api/session/<session_id>/note/`를 공통으로 사용합니다.

## 공통 풀이 페이지

- 공통 화면은 문제 렌더링, 선택지 선택/해제, 이전/다음 이동, 문항 목록, 타이머를 같이 사용합니다.
- 문제풀이(`practice`)는 기존처럼 조건 기반 문제 생성, 이어풀기, 답안 즉시 저장, 나가기 시 자동 저장을 사용합니다.
- 진단평가(`diagnostic`)는 `sessionStorage.diagnosisSession`의 문제를 불러오고, 제출 시 `POST /diagnosis/api/submit/`에 한 번에 저장합니다.
- 진단평가 시작 세션은 고정 `user_id = 1` 대신 로그인 사용자 `request.user.user_id`로 생성합니다.

## 문제풀이 결과 API

```text
GET /question/api/session/<session_id>/result/
```

- 제출 완료된 문제풀이 세션(`solve_sessions.status = completed`)만 조회합니다.
- `solve_records` 기준으로 사용자 선택 답안, 정오답, 풀이 시간, 저장 여부를 반환합니다.
- `questions`, `question_options` 기준으로 문제 지문, 선택지, 정답, 해설, 핵심 개념을 함께 반환합니다.
- 결과 페이지는 이 API를 먼저 사용하고, 실패하면 기존 `localStorage.questionResult`를 보조 수단으로 사용합니다.

## 진단평가 쪽 참고 사항

- 진단평가는 현재 `diagnosis` 앱의 기존 결과 API를 사용합니다.
- 진단평가 시작 로직의 고정 `user_id`는 로그인 사용자 기반으로 변경했습니다.
- 진단평가 선택지는 시작 API에서 셔플되어 표시 번호가 다시 붙습니다. 제출 후 결과 화면의 사용자 답안 번호가 표시 번호와 정확히 일치해야 한다면, `diagnosis_submit`에서 화면 표시 번호도 함께 저장하도록 추가 조정이 필요합니다.

## 노트 화면 세션 유형 필터

- 노트 화면(`/user/wrong-note/`)은 `solve_sessions.session_type` 기준으로 세션 유형을 구분합니다.
- 필터 값은 전체, 진단평가(`diagnostic`), 문제풀이(`practice`)입니다.
- 전체 보기, 오답 보기, 저장 문제 보기 모두 세션 유형 필터를 함께 적용합니다.

## 앞으로 공통 페이지 작업 시 합의할 부분

- 문제풀이와 진단평가가 공통 결과 페이지를 계속 사용할 경우, 최종 응답 데이터 이름을 최대한 맞추는 것이 좋습니다.
- 노트에서는 `session_type`으로 진단평가와 문제풀이를 구분하므로, 진단평가도 `solve_sessions`, `solve_records` 구조를 유지하는 편이 연결 비용이 낮습니다.
