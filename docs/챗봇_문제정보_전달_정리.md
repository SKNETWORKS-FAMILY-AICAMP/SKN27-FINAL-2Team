# 결과 페이지에서 챗봇으로 문제 정보 전달 정리

## 1. 현재 구현 상태

결과 페이지에서 `챗봇에게 질문` 버튼을 누르면 챗봇 페이지로 이동합니다.
다만 현재 방식은 API로 문제 정보를 넘기는 구조가 아닙니다.

현재는 브라우저의 `sessionStorage`에 문제 정보를 임시 저장한 뒤, `/chatbot/` 페이지로 이동하는 구조입니다.

```text
결과 페이지
→ sessionStorage에 문제 정보 저장
→ /chatbot/ 페이지로 이동
→ 챗봇 페이지에서 sessionStorage 값을 읽어야 함
```

현재 문제는 챗봇 페이지에서 `sessionStorage` 값을 읽는 코드가 없어서, 챗봇으로 이동만 하고 문제 정보가 사용되지 않는다는 점입니다.

## 2. 결과 페이지에서 주는 정보

### 일반 문제 풀이 결과 페이지

파일:

```text
app/templates/question/question_result.html
```

버튼 클릭 위치:

```javascript
document.getElementById("askChatbot").addEventListener("click", () => {
  sessionStorage.setItem("chatbotQuestionContext", buildChatContext(currentIndex));
  window.location.href = "/chatbot/?from=question-result";
});
```

저장하는 key:

```text
chatbotQuestionContext
```

저장하는 값:

```text
현재 선택된 문제의 context 문자열
```

포함되는 정보:

```text
- 기본 요청 문장
- 문제 제목
- 지문
- 보기/선지
- 내가 선택한 답
- 정답
- 정답/오답 결과
- 풀이 시간
- 분류 정보
  - 시대
  - 주제
  - 문항 유형
  - 세부 유형
- 핵심 개념
- 해설
```

즉 결과 페이지는 문제 객체 전체를 JSON으로 넘기는 것이 아니라, 챗봇에게 바로 질문으로 사용할 수 있는 하나의 긴 문자열을 만들어 저장합니다.

## 3. 진단 평가 결과 페이지에서 주는 정보

파일:

```text
app/templates/diagnosis/result.html
```

버튼 클릭 위치:

```javascript
document.getElementById("askChatbot").addEventListener("click", () => {
  sessionStorage.setItem("chatbotQuestionContext", buildChatContext(explanations[currentIndex]));
  window.location.href = "/chatbot/?from=diagnosis-result";

```

저장하는 key:

```text
chatbotQuestionContext
```

포함되는 정보:

```text
- 기본 요청 문장
- 문제 내용
- 분류 정보
  - 시대
  - 주제
  - 문항 유형
- 보기/선지
- 내가 선택한 답
- 정답
- 정답/오답 결과
- 풀이 시간
- 핵심 개념
- 해설
```

일반 문제 풀이 결과 페이지와 거의 같은 구조입니다.

## 4. 저장 위치

문제 정보는 서버 DB나 API에 저장되는 것이 아니라, 브라우저의 `sessionStorage`에 저장됩니다.

```javascript
sessionStorage.setItem("chatbotQuestionContext", contextText);
```

특징:

```text
- 같은 브라우저 탭 안에서만 유지됨
- 탭을 닫으면 사라짐
- 서버에는 저장되지 않음
- URL query string으로 문제 정보가 노출되지 않음
- 로그인 여부와 별개로 브라우저 임시 저장소에 저장됨
```

따라서 현재 전달 방식은 “프론트엔드 임시 전달 방식”입니다.

## 5. 챗봇에서 받아와야 하는 정보

챗봇 페이지 파일:

```text
app/templates/chatbot/chat.html
```

챗봇 페이지에서 읽어야 하는 값:

```javascript
const context = sessionStorage.getItem("chatbotQuestionContext");
```

읽은 뒤에는 재사용되지 않도록 삭제하는 것이 좋습니다.

```javascript
sessionStorage.removeItem("chatbotQuestionContext");
```

챗봇에서 사용할 수 있는 방식은 크게 3가지입니다.

## 6. 챗봇에서 사용하는 방식

### 방식 1. 입력창에 자동으로 넣기

가장 단순한 방식입니다.

```text
챗봇 페이지 진입
→ sessionStorage에서 문제 정보 읽기
→ 입력창에 문제 정보 채우기
→ 사용자가 직접 전송
```

장점:

```text
- 사용자가 질문 내용을 확인하고 수정 가능
- 자동 호출이 아니라 안전함
```

단점:

```text
- 사용자가 한 번 더 전송 버튼을 눌러야 함
```

### 방식 2. 챗봇에 자동 질문하기

현재 목적에 가장 가까운 방식입니다.

```text
챗봇 페이지 진입
→ sessionStorage에서 문제 정보 읽기
→ 기존 submitChatQuestion()에 전달
→ 자동으로 RAG API 호출
→ 챗봇 답변 표시
```

이때 새 API를 만들 필요는 없습니다.
이미 챗봇은 아래 API를 사용하고 있습니다.

```text
chatbot:rag_chat_api
```

실제 요청은 `chat.html` 안에서 `fetch`로 처리됩니다.

```javascript
fetch("{% url 'chatbot:rag_chat_api' %}", {
  method: "POST",
  body: JSON.stringify({
    question,
    display_question: displayQuestion,
    session_id: activeSessionId,
    mode,
    intent,
    answer_format: answerFormat,
    top_k: 5,
    conversation_history: conversationHistory,
  }),
});
```

따라서 결과 페이지에서 저장한 문제 context를 `question` 값으로 넘기면 됩니다.

### 방식 3. 문제 카드로 먼저 보여주고 버튼 선택하게 하기

현재 챗봇에는 이미 “저장된 문제 선택” 기능이 있습니다.
이 기능은 문제를 카드로 보여주고, 사용자가 `문제 풀어보기` 또는 `다른 질문하기`를 누르는 구조입니다.

관련 함수:

```text
selectProblemForChat(problem)
buildProblemContext(problem, prompt)
appendProblemActionMessage(problem)
```

다만 결과 페이지에서 저장하는 값은 현재 문자열이고, `selectProblemForChat(problem)`은 문제 객체를 기대합니다.
그래서 이 방식을 쓰려면 결과 페이지에서 문자열이 아니라 JSON 형태의 문제 객체를 저장하도록 구조를 바꾸는 것이 더 좋습니다.

## 7. 지금 필요한 연결 작업

현재 빠진 부분은 챗봇 페이지의 초기 로딩 시점에 아래 흐름을 추가하는 것입니다.

```text
1. /chatbot/ 페이지 진입
2. sessionStorage.getItem("chatbotQuestionContext") 확인
3. 값이 있으면 가져오기
4. sessionStorage.removeItem("chatbotQuestionContext")로 삭제
5. 가져온 문제 정보를 submitChatQuestion()에 전달
6. intent는 "question"으로 지정
```

권장 흐름:

```text
문제 결과 페이지 → 챗봇 자동 질문
```

사용할 값:

```text
question: sessionStorage에서 꺼낸 문제 context 전체
display_question: "이 문제 설명해줘" 또는 짧은 표시용 문장
intent: "question"
historyContext: 문제 context 전체
```

## 8. API 연결 여부 정리

현재 문제 정보 전달 자체는 API가 아닙니다.

```text
결과 페이지 → 챗봇 페이지
= sessionStorage 사용
```

챗봇 답변 생성은 API입니다.

```text
챗봇 페이지 → 서버 RAG 답변 생성
= chatbot:rag_chat_api 사용
```

따라서 새로 연결해야 하는 것은 API가 아니라, 챗봇 페이지에서 `sessionStorage` 값을 읽어서 기존 `rag_chat_api` 호출 흐름에 태우는 부분입니다.

## 9. 결론

현재 구현은 절반만 되어 있습니다.

```text
결과 페이지에서 문제 정보를 저장하는 부분: 있음
챗봇 페이지에서 문제 정보를 읽는 부분: 없음
챗봇 답변 API: 이미 있음
```

따라서 구현 방향은 다음과 같습니다.

```text
chat.html에서 chatbotQuestionContext를 읽는다.
읽은 값을 기존 submitChatQuestion()에 넘긴다.
intent는 question으로 지정한다.
처리 후 sessionStorage에서 삭제한다.
```

이렇게 하면 `챗봇에게 질문` 버튼을 눌렀을 때 단순히 챗봇으로 이동하는 것이 아니라, 해당 문제 정보를 기반으로 바로 챗봇 질문까지 이어질 수 있습니다.
