# 선지 검수 모델 배포 방식 및 비용 비교

## 1. 목적

이 문서는 선지 단위 2차 검수 모델을 실제 팀원이 사용할 때, 어떤 방식으로 배포하는 것이 좋은지 비교하기 위한 문서입니다.

비교 대상은 다음 2가지입니다.

```text
AWS EC2 GPU 서버
RunPod Serverless
```

결론부터 말하면, 현재 프로젝트처럼 **문제 생성 후 필요할 때만 검수하는 구조**라면 `RunPod Serverless Flex`가 가장 적합합니다.

## 2. 배포한다는 의미

모델을 서버 API로 배포한다는 것은, 학습된 모델을 사람이 직접 노트북에서 실행하는 것이 아니라 **HTTP 요청으로 호출할 수 있게 만드는 것**입니다.

예를 들어 팀원이 문제 JSON을 보내면 다음처럼 요청합니다.

```text
POST /review-question
```

서버는 내부에서 모델을 실행하고 다음과 같은 결과를 반환합니다.

```json
{
  "question_id": "q_001",
  "choices": [
    {
      "choice_no": 1,
      "status": "통과",
      "label": 1,
      "error_codes": []
    },
    {
      "choice_no": 2,
      "status": "검수필요",
      "label": 0,
      "error_codes": ["CHOICE_FORMAT_ERROR"]
    }
  ]
}
```

즉, 문제 생성 팀원은 모델 코드를 직접 실행하지 않고 API만 호출하면 됩니다.

## 3. 비용 계산 기준

모델은 `klue/roberta-base` 기반 선지 단위 이진 분류 모델입니다.

문제 1개는 5지선다 기준으로 계산했습니다.

```text
문제 1개 = 선지 5개 검사
```

계산 가정은 다음과 같습니다.

```text
문제 1개 처리 시간: 약 1초
문제 100개 batch 처리 시간: 약 30초
문제 1000개 batch 처리 시간: 약 240초

RunPod Serverless cold start: 약 60초
RunPod idle timeout: 약 5초

AWS EC2 필요할 때만 켜는 경우:
서버 시작 + 모델 로드 시간 약 5분
```

실제 비용은 Docker 이미지 크기, 모델 로딩 방식, batch 처리 여부, GPU 종류, 리전, 네트워크/스토리지 비용에 따라 달라질 수 있습니다.

## 4. 기준 단가

| 항목 | 기준 단가 |
|---|---:|
| AWS EC2 `g4dn.xlarge` | 약 `$0.526/hour` |
| RunPod Serverless Flex RTX 4000/A4000급 | 약 `$0.00016/second` |
| RunPod Serverless Active RTX 4000/A4000급 | 약 `$0.00011/second` |

AWS EC2는 서버가 켜져 있는 동안 비용이 발생합니다.

RunPod Serverless Flex는 worker가 실행되는 시간만 비용이 발생합니다.

## 5. RunPod Serverless Flex

RunPod Serverless Flex는 요청이 있을 때 worker가 실행되고, 요청이 없으면 scale down 되는 방식입니다.

간헐적으로 검수 요청이 들어오는 경우 가장 비용 효율적입니다.

### 예상 비용

| 문제 수 | 예상 실행 시간 | 예상 비용 | 문제당 비용 |
|---:|---:|---:|---:|
| 1개 | 약 66초 | 약 `$0.0106` | 약 `$0.0106` |
| 100개 | 약 95초 | 약 `$0.0152` | 약 `$0.000152` |
| 1000개 | 약 305초 | 약 `$0.0488` | 약 `$0.000049` |

계산식은 다음과 같습니다.

```text
비용 = 실행초 × 0.00016
```

예를 들어 1000문제는 다음처럼 계산합니다.

```text
60초 cold start + 240초 처리 + 5초 idle
= 305초

305 × 0.00016
= $0.0488
```

### 사용하는 이유

- 요청이 있을 때만 비용이 발생합니다.
- 항상 GPU 서버를 켜둘 필요가 없습니다.
- 프로젝트 데모, 팀 내부 검수, 간헐적 batch 검수에 적합합니다.
- 100개 또는 1000개 단위로 batch 처리하면 문제당 비용이 매우 낮아집니다.

### 단점

- 처음 요청할 때 cold start가 발생할 수 있습니다.
- 요청을 1개씩 자주 보내면 batch보다 비효율적입니다.
- Docker 이미지와 모델 로딩 최적화가 필요할 수 있습니다.

## 6. RunPod Serverless Active Worker

Active Worker는 Serverless 구조이지만 worker를 계속 켜두는 방식입니다.

응답 속도는 빠르지만 요청이 없어도 비용이 발생합니다.

### 고정 비용

| 켜두는 시간 | 예상 비용 |
|---:|---:|
| 1시간 | 약 `$0.396` |
| 1일 | 약 `$9.50` |
| 1개월, 730시간 | 약 `$289.08` |

계산식은 다음과 같습니다.

```text
0.00011 × 3600 = $0.396/hour
```

월 기준 문제당 비용은 다음과 같습니다.

| 월 문제 수 | 월 비용 | 문제당 비용 |
|---:|---:|---:|
| 1개 | 약 `$289.08` | 약 `$289.08` |
| 100개 | 약 `$289.08` | 약 `$2.89` |
| 1000개 | 약 `$289.08` | 약 `$0.289` |

### 사용하는 이유

- API 응답 속도를 빠르게 유지할 수 있습니다.
- cold start를 피할 수 있습니다.
- 검수 요청이 하루 종일 계속 들어오는 경우 적합합니다.

### 단점

- 요청이 없어도 계속 비용이 발생합니다.
- 현재 프로젝트처럼 필요할 때만 검수하는 구조에서는 비효율적입니다.

## 7. AWS EC2 GPU 서버

AWS EC2 GPU 서버는 GPU 인스턴스를 직접 켜고, FastAPI 같은 서버를 띄워서 사용하는 방식입니다.

예시는 `g4dn.xlarge`입니다.

```text
g4dn.xlarge
GPU: NVIDIA T4 1개
가격: 약 $0.526/hour
```

### 항상 켜두는 경우

| 켜두는 시간 | 예상 비용 |
|---:|---:|
| 1시간 | 약 `$0.526` |
| 1일 | 약 `$12.62` |
| 1개월, 730시간 | 약 `$383.98` |

월 기준 문제당 비용은 다음과 같습니다.

| 월 문제 수 | 월 비용 | 문제당 비용 |
|---:|---:|---:|
| 1개 | 약 `$383.98` | 약 `$383.98` |
| 100개 | 약 `$383.98` | 약 `$3.84` |
| 1000개 | 약 `$383.98` | 약 `$0.384` |

### 사용하는 이유

- AWS 인프라를 이미 사용하고 있을 때 적합합니다.
- VPC, IAM, S3, CloudWatch 등 AWS 관리 기능과 연동하기 좋습니다.
- 항상 켜진 안정적인 API 서버가 필요한 경우 좋습니다.
- 운영 환경에서 접근 제어, 로그 관리, 모니터링을 붙이기 쉽습니다.

### 단점

- 서버가 켜져 있으면 요청이 없어도 계속 비용이 발생합니다.
- RunPod Serverless보다 배포와 운영이 복잡합니다.
- GPU 서버를 계속 켜두면 비용이 큽니다.

## 8. AWS EC2를 필요할 때만 켜는 경우

AWS EC2도 필요할 때만 켜고, 검수 후 끄는 방식으로 사용할 수 있습니다.

이 경우 서버 시작과 모델 로딩 시간이 필요합니다.

```text
서버 시작 + 모델 로드 시간: 약 5분 가정
```

### 예상 비용

| 문제 수 | 예상 실행 시간 | 예상 비용 | 문제당 비용 |
|---:|---:|---:|---:|
| 1개 | 약 301초 | 약 `$0.044` | 약 `$0.044` |
| 100개 | 약 330초 | 약 `$0.048` | 약 `$0.00048` |
| 1000개 | 약 540초 | 약 `$0.079` | 약 `$0.000079` |

계산식은 다음과 같습니다.

```text
비용 = 실행초 × (0.526 / 3600)
```

서버 시작과 모델 로드가 10분 걸리면 비용은 대략 다음과 같습니다.

| 문제 수 | 예상 비용 |
|---:|---:|
| 1개 | 약 `$0.088` |
| 100개 | 약 `$0.092` |
| 1000개 | 약 `$0.123` |

### 사용하는 이유

- AWS를 꼭 써야 하지만 항상 서버를 켜둘 필요가 없을 때 사용합니다.
- 하루에 한두 번 batch 검수하는 경우 사용할 수 있습니다.

### 단점

- 서버를 켜고 끄는 자동화가 필요합니다.
- 시작 시간이 길 수 있습니다.
- RunPod Serverless보다 운영이 번거롭습니다.

## 9. 방식별 비교

| 방식 | 비용 | 응답 속도 | 운영 난이도 | 추천 상황 |
|---|---:|---:|---:|---|
| RunPod Serverless Flex | 낮음 | 첫 요청은 느릴 수 있음 | 보통 | 가끔 검수, batch 검수 |
| RunPod Serverless Active | 중간 | 빠름 | 보통 | 자주 호출, cold start 회피 |
| AWS EC2 항상 켜기 | 높음 | 빠름 | 높음 | 운영 서버, AWS 연동 필요 |
| AWS EC2 필요할 때만 켜기 | 낮음~중간 | 시작 느림 | 높음 | AWS를 꼭 써야 하는 batch 검수 |

## 10. 최종 추천

현재 프로젝트에는 `RunPod Serverless Flex`를 추천합니다.

이유는 다음과 같습니다.

```text
검수 요청이 항상 발생하는 서비스가 아님
문제 생성 후 필요할 때만 검수하면 됨
GPU 서버를 계속 켜둘 필요가 없음
batch 처리 시 비용이 매우 낮음
프로젝트 데모와 팀 내부 사용에 적합함
```

추천 흐름은 다음과 같습니다.

```text
문제 생성 팀원
→ 생성 문제 JSON batch 전달
→ RunPod Serverless endpoint 호출
→ 선지별 검수 결과 JSON 반환
→ 검수필요/참고검수 확인
```
