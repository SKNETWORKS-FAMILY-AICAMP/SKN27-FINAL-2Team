# v9 결과 오류 유형 분석

## 1. 요약

v9 결과에서 기출문제의 오류처럼 보이는 항목은 대부분 모델이 직접 오류로 판단한 것이 아니라, 규칙 검사에서 걸린 `참고검수` 항목이다.

반대로 팀원 생성 문제에서는 모델이 직접 `검수필요`로 판단한 항목이 많고, 특히 `WEIRD_CHOICE`가 많이 나타났다. 이는 실제로 문항 품질을 다시 확인해야 하는 후보로 볼 수 있다.

## 2. 전체 test 결과

```text
test 전체 선지: 2,065개
기출 선지: 1,535개
팀원 생성 선지: 530개

실제 오류 선지: 117개
실제 정상 선지: 1,948개
```

모델 단독 기준:

```text
실제 오류 117개 중 107개 탐지
실제 오류 10개 미탐
정상 1,948개 중 16개 오탐
```

## 3. 기출문제에서 발생한 오류처럼 보이는 항목

기출문제 1,535개 중 `final_label=0`으로 표시된 항목은 80개다.

하지만 이 중 모델이 직접 오류로 판단한 것은 1개뿐이고, 나머지 79개는 규칙 검사만 걸린 항목이다.

```text
기출 선지 총합: 1,535개
모델이 오류로 판단: 1개
규칙 검사만 걸림: 79개
```

기출에서 규칙 검사에 걸린 코드:

```text
QUESTION_MARKER_MISMATCH: 40개
ANSWER_LENGTH_BIAS: 36개
CHOICE_FORMAT_ERROR: 8개
ANSWER_IN_PASSAGE: 8개
```

중복 조합 기준:

```text
QUESTION_MARKER_MISMATCH: 33개
ANSWER_LENGTH_BIAS: 24개
CHOICE_FORMAT_ERROR: 8개
ANSWER_LENGTH_BIAS|QUESTION_MARKER_MISMATCH: 7개
ANSWER_IN_PASSAGE|ANSWER_LENGTH_BIAS: 5개
ANSWER_IN_PASSAGE: 3개
```

## 4. 기출 오탐 원인

기출 오탐은 대부분 실제 오류라기보다 전처리/규칙 조건 문제로 보인다.

### 4-1. ANSWER_LENGTH_BIAS

기출에는 다음과 같은 정상 유형이 있다.

```text
ㄱ, ㄴ
ㄷ, ㄹ
(가)
원산 학사
수원 화성 건설
㉣
```

이런 선지는 짧지만 시험 형식상 정상이다.  
현재 규칙은 정답 선지가 너무 짧으면 `ANSWER_LENGTH_BIAS` 후보로 잡기 때문에 오탐이 발생했다.

### 4-2. QUESTION_MARKER_MISMATCH

연표형/지도형/시기 선택형 문제에서는 선지가 `(가)`, `(나)`, `(다)`처럼 표시되는 경우가 정상이다.

하지만 전처리된 text에는 연표, 지도, 표 구조가 충분히 들어오지 않아서 규칙이 `지문에 없는 표식 참조`로 오판했다.

예:

```text
다음 사건이 일어난 시기를 연표에서 옳게 고른 것은?
선지: (가), (나), (다), (라), (마)
```

이 경우 실제 문제에는 연표가 있어야 정상 판단이 가능하다.

### 4-3. CHOICE_FORMAT_ERROR

기출 선지에 `FTA`, `IMF` 같은 영어 약어가 들어간 경우가 있다.

현재 규칙은 영어가 포함된 선지를 형식 오류 후보로 볼 수 있기 때문에, 정상 기출도 일부 오탐된다.

## 5. 팀원 생성 문제 결과

팀원 생성 문제 test 선지는 총 530개다.

```text
팀원 생성 선지: 530개
실제 오류 라벨: 117개
실제 정상 라벨: 413개
모델이 오류로 판단한 선지: 122개
최종 검수 대상: 123개
```

모델 기준:

```text
실제 오류 117개 중 107개 탐지
실제 오류 10개 미탐
실제 정상 라벨 413개 중 15개를 오류로 판단
```

단, 이 15개는 라벨상 정상일 뿐 실제로는 문항 품질이 낮을 수 있다.  
팀원 생성 문제에서는 라벨이 완전히 깨끗하지 않을 가능성이 있다.

## 7. 모델이 예측한 팀원 생성 문제 오류 코드

팀원 생성 문제 test 결과에서 최종 오류 코드 분포:

```text
WEIRD_CHOICE: 96개
ANSWER_LENGTH_BIAS: 26개
ANSWER_IN_PASSAGE|ANSWER_LENGTH_BIAS: 1개
```

`WEIRD_CHOICE`가 많은 이유는 모델이 이상하다고 판단했지만, 규칙 기반 코드로는 명확하게 `ANSWER_IN_PASSAGE`, `ANSWER_LENGTH_BIAS` 등으로 특정되지 않았기 때문이다.

즉, `WEIRD_CHOICE`는 명확한 규칙 오류라기보다 사람이 직접 재검토해야 하는 모델 기반 후보에 가깝다.

## 8. WEIRD_CHOICE가 많이 발생하는 이유

가능한 원인은 다음과 같다.

```text
1. 팀원 생성 문제의 문체가 기출문제 문체와 다르다.
2. 선지가 지문을 자연스럽게 활용하기보다 지문 내용을 그대로 요약하거나 반복한다.
3. 질문은 '다음 제도/대상에 대한 설명'인데 선지는 너무 일반적이거나 애매하다.
4. 라벨상 정상 선지라도 실제로는 문항 품질이 낮은 경우가 있다.
5. 모델은 이상하다고 봤지만 현재 오류 코드 규칙이 그 이유를 세분화하지 못한다.
```

따라서 `WEIRD_CHOICE`는 무조건 폐기가 아니라, 사람이 지문/질문/선지를 보고 실제 오류 여부를 판단해야 한다.

## 9. 다음 개선 방향

### 9-1. 기출 오탐 줄이기

다음 유형은 규칙 검사에서 예외 처리하는 것이 좋다.

```text
보기형 문제: ㄱ, ㄴ / ㄷ, ㄹ
연표형 문제: (가), (나), (다), (라), (마)
지도형 문제: ㉠, ㉡, ㉢, ㉣
퀴즈형 짧은 정답: 원산 학사, 수원 화성 건설 등
영어 약어: FTA, IMF, APEC, UN 등
```

### 9-2. 전처리 개선

연표, 지도, 표, 보기 정보가 있는 문제는 현재 text에 충분히 반영되지 않을 수 있다.

따라서 전처리 시 다음 정보를 보존해야 한다.

```text
연표의 시기 정보
지도/표의 라벨 정보
보기 ㄱ~ㄹ 내용
이미지/OCR에서 나온 구조 정보
```

### 9-3. 팀원 생성 문제 라벨 보강

`WEIRD_CHOICE`로 잡힌 선지를 사람이 직접 확인한 뒤 다음처럼 기록하면 다음 학습에 도움이 된다.

```text
실제 오류 여부
정확한 오류 코드
오탐 여부
수정 의견
```

이 기록을 다음 학습 데이터에 반영하면 `WEIRD_CHOICE`를 더 구체적인 오류 코드로 분리할 수 있다.
