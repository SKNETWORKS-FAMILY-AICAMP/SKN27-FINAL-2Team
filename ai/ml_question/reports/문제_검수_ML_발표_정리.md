# 문제 검수 ML 발표 정리

## 1. 개발 목적

문제 생성 팀원이 만든 한국사 5지선다 문제를 바로 사용하지 않고, 배포 전에 한 번 더 확인하기 위한 **2차 검수 ML 모델**을 개발하였다.

이 모델의 목적은 문제의 정답을 맞히는 것이 아니라, 생성된 문제 안에서 **품질상 이상 가능성이 있는 선지**를 먼저 찾아 검수자가 우선 확인할 수 있게 하는 것이다.

```text
문제 자동 폐기 모델 X
정답 예측 모델 X
선지 단위 오류 후보 추출 모델 O
검수 우선순위 제공 모델 O
```

## 2. 문제 정의

기존 문제 생성 결과는 문항 단위로 제공되지만, 실제 오류는 문항 전체가 아니라 특정 선지 1개에서 발생하는 경우가 많다.

예를 들어 문항이 사용 불가로 판단된 이유가 `정답 선지가 지문에 그대로 노출됨`이라면, 실제 오류 선지는 정답 선지 1개이고 나머지 오답 선지 4개는 정상일 수 있다.

따라서 이번 ML 작업은 문항 단위가 아니라 **선지 단위 이진 분류**로 설계하였다.

```text
문항 1개
→ 선지 1번 검수
→ 선지 2번 검수
→ 선지 3번 검수
→ 선지 4번 검수
→ 선지 5번 검수
```

## 3. 모델 입력 데이터

모델은 선지 하나만 보는 것이 아니라, 해당 선지가 어떤 문항 안에 있는지 함께 판단한다.

입력 데이터는 다음 4개를 사용한다.

```text
지문 + 질문 + 선지 1개 + 정답 여부
```

예시:

```text
지문: 세종 28년에 새로 만들어진 글자를 풀이한 한문 해설서이다...
질문: 다음 자료에 대한 설명으로 옳은 것은?
선지: 간송미술관 소장본이 대표적이다.
정답 여부: 정답
```

## 4. y값

학습 y값은 이진 분류로 구성하였다.

```text
label = 0: 오류 있음
label = 1: 오류 없음
```

모델은 선지가 정답인지 아닌지를 맞히는 것이 아니라, **해당 선지가 문제 품질상 이상한지 아닌지**를 분류한다.

## 5. 사용 모델

사용 모델은 `klue/roberta-base`이다.

사용 이유:

- 한국어 문장 분류에 적합한 BERT/RoBERTa 계열 모델이다.
- 입력이 `지문`, `질문`, `선지`처럼 여러 문장의 관계를 봐야 하는 구조이다.
- GPT처럼 새 문장을 생성하는 작업이 아니라, 주어진 텍스트를 읽고 오류 여부를 분류하는 작업이다.
- 프로젝트 목적이 2차 검수 보조이므로 비교적 가볍고 배포가 쉬운 모델이 적합하다.

## 6. 사용 데이터

학습 데이터는 크게 두 종류를 사용하였다.

| 데이터 | 사용 목적 |
|---|---|
| 기출 문제 데이터 | 정상 선지 데이터로 사용 |
| 팀원 생성 사용불가 문제 데이터 | 오류 후보 선지 데이터로 사용 |

단, 팀원 생성 문제가 문항 단위로 실패 데이터라고 해도 선지 5개가 모두 오류라고 볼 수는 없다. 그래서 문항을 선지 단위로 분리한 뒤, 오류 조건에 해당하는 선지를 중심으로 라벨링하였다.

## 7. 오류 코드

모델의 학습 목표는 이진 분류이지만, 사람이 결과를 해석할 수 있도록 오류 코드도 함께 제공한다.

오류 코드는 모델의 y값이 아니라 **검수 설명용 보조 정보**이다.

| 오류 코드 | 의미 |
|---|---|
| `ANSWER_IN_PASSAGE` | 정답 선지가 지문에 직접 노출됨 |
| `ANSWER_RESTATEMENT_SUSPECT` | 정답 선지가 지문 내용을 거의 재진술함 |
| `ANSWER_LENGTH_BIAS` | 정답 선지가 다른 선지보다 유독 길거나 짧음 |
| `CHOICE_FORMAT_ERROR` | 선지 문장 또는 형식이 어색함 |
| `ODD_DISTRACTOR` | 오답 선지가 너무 이상하거나 문제 맥락에서 튐 |
| `QUESTION_CHOICE_MISMATCH` | 질문 요구와 선지 형식이 맞지 않아 보임 |

`QUESTION_CHOICE_MISMATCH`는 오탐 가능성이 있어 최종 v15에서는 자동 오류가 아니라 **참고 코드**로만 사용한다.

## 8. 개발 과정 및 성능 개선

초기에는 데이터 구성과 평가 방식이 충분히 안정적이지 않아 성능 수치가 실제 검수 성능을 잘 설명하지 못했다. 이후 데이터 라벨링 방식, 오류 코드 처리, threshold, 제외 대상 선지를 계속 수정하면서 최종 v15까지 개선하였다.

성능 비교에서 중요한 지표는 `abnormal_recall`과 `abnormal_f1`이다.

```text
abnormal_recall
실제 오류 선지 중 모델이 얼마나 많이 잡았는지

abnormal_f1
오류 선지를 잡는 능력과 오탐을 함께 고려한 점수
```

### v15 성능이 v14보다 낮아진 이유

v15는 v14보다 Accuracy, Precision, Recall, F1이 조금 낮아졌다.

| 비교 | v14 | v15 | 변화 |
|---|---:|---:|---:|

| 오류 Precision | 89.08% | 84.76% | -4.32%p |
| 오류 Recall | 90.60% | 85.58% | -5.02%p |
| 오류 F1 | 89.83% | 85.17% | -4.66%p |
| 테스트 선지 수 | 2,065 | 1,900 | -165개 |
| 오류 선지 수 | 117 | 104 | -13개 |

성능이 낮아진 이유는 모델 자체가 단순히 나빠졌다기보다, v15에서 평가 대상이 바뀌었기 때문이다.

v15에서는 `ㄱ, ㄴ` 조합형 선지와 `(가)-(나)-(다)` 순서형 선지 165개를 선지 단위 ML 검수 대상에서 제외하였다. 이 유형은 선지 하나만 보고 오류 여부를 판단하기 어렵기 때문에, 운영 기준상 제외하는 것이 더 적절하다고 판단했다.

따라서 v15는 수치상 최고 성능 버전은 아니지만, 실제 사용 목적에 더 맞게 검수 범위를 정리한 최종 운영 버전이다.

최종 운영에서는 모델 결과에 규칙 기반 오류 검사를 함께 적용한다.

검수필요로 나온 오류 코드 분포:

| `ODD_DISTRACTOR` | 5 |
| `ANSWER_IN_PASSAGE` | 4 |

팀원 생성 문제 기준으로 보면:

## 11. threshold 기준

모델은 내부적으로 `error_prob`를 계산한다.

```text
error_prob = 해당 선지가 오류일 확률
```

최종 v15에서는 threshold를 `0.1`로 고정하였다.

```text
error_prob >= 0.1
→ 오류 후보

error_prob < 0.1
→ 통과
```

threshold를 낮게 잡은 이유는 이 모델이 자동 폐기 모델이 아니라 **2차 검수 후보 추출 모델**이기 때문이다. 즉, 오탐이 조금 늘어나더라도 실제 오류를 놓치지 않는 방향을 우선하였다.

## 12. 최종 사용 흐름

팀원이 실제로 사용할 때는 다음 흐름으로 사용한다.

```text
1. 문제 생성
2. 생성 문제를 JSON 형식으로 저장
3. predict_choice_quality.py 실행
4. review.csv 생성
5. 검수필요 선지 먼저 확인
6. 오류코드를 참고하여 문제 수정
7. 수정 후 필요하면 다시 검수 실행
```

입력 JSON 예시:

```json
[
  {
    "question_id": "q_001",
    "material": "지문 내용",
    "question": "질문 내용",
    "answer_number": 3,
    "choices": [
      {"number": 1, "text": "1번 선지"},
      {"number": 2, "text": "2번 선지"},
      {"number": 3, "text": "3번 선지"},
      {"number": 4, "text": "4번 선지"},
      {"number": 5, "text": "5번 선지"}
    ]
  }
]
```

실행 예시:

```bash
python predict_choice_quality.py \
  --model_dir ./model \
  --input ./generated_questions.json \
  --output_csv ./review.csv \
  --output_json ./review.json
```

## 14. 한계점

현재 모델은 2차 검수 보조 모델이므로 다음 한계가 있다.

- 역사적 사실 자체의 참/거짓 검증은 어렵다.
- 문항 전체 논리나 복잡한 사료 해석은 완전히 판단하기 어렵다.
- 오류 코드별 데이터 수가 충분하지 않은 항목은 설명 정확도가 제한된다.
- 선지 단위 판단이 어려운 조합형/순서형 선지는 별도로 제외 처리하였다.

따라서 최종 사용 방향은 다음과 같다.

```text
자동 폐기 X
자동 정답 검증 X
사람 검수 전 오류 후보 추출 O
검수 우선순위 제공 O
```

## 15. 최종 결론

최종 모델은 `v15`이다.

v15를 최종으로 선택한 이유:

- 선지 단위 이진 분류라는 목표에 맞게 데이터 구조를 정리하였다.
- 모델 결과와 규칙 기반 오류 코드를 함께 제공하여 사람이 해석하기 쉽다.
- `ㄱ, ㄴ` 조합형과 `(가)-(나)-(다)` 순서형처럼 선지 단위 판단이 어려운 유형을 제외하였다.
- 최종 기준 오류 Recall이 92.31%로, 실제 오류를 최대한 놓치지 않는 2차 검수 목적에 적합하다.

최종적으로 이 모델은 생성된 한국사 문제를 바로 배포하기 전에, 사람이 우선 확인해야 할 선지를 빠르게 추려주는 **선지 단위 문제 품질 검수 ML 모델**이다.
