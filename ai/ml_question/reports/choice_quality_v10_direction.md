# v10 개선 방향 및 WEIRD_CHOICE/오답 선지 분석

## 1. v10에 반영한 내용

v9 결과에서 기출문제의 참고검수 오탐이 많았다.  
대부분 실제 오류가 아니라 시험 형식상 정상인 짧은 선지나 표식 선지를 규칙이 과하게 잡은 경우였다.

v10에는 다음 예외를 반영했다.

```text
ㄱ, ㄴ / ㄷ, ㄹ 같은 보기 조합 선지
(가), (나), (다) 같은 연표/시기/지도 선택 선지
㉠, ㉡ 같은 지도형/위치형 선지
FTA, IMF, APEC, UN 같은 정상 영어 약어
퀴즈형/빈칸형 짧은 정답
```

이 수정은 모델 학습 목적을 바꾸는 것이 아니라, 결과 저장 단계의 규칙 검사 오탐을 줄이기 위한 것이다.

추가로 `ANSWER_LENGTH_BIAS` 기준에서 절대 길이 기준을 제거했다.

기존에는 정답 선지가 8글자 이하이면 길이 편향 후보로 볼 수 있었지만, 이 기준은 모든 선지가 짧은 보기형 문제에서 오탐을 만들 수 있다.  
따라서 v10 현재 기준은 **정답 선지를 제외한 다른 선지들의 평균/중앙값과 비교해 유독 짧거나 긴 경우**만 길이 편향으로 본다.

결과 CSV에는 길이 판단 근거를 확인할 수 있도록 다음 컬럼을 추가했다.

```text
선지길이
다른선지평균길이
다른선지중앙값길이
평균대비길이차이
중앙값대비길이비율
```

## 2. 보류한 내용

연표, 지도, 표, 이미지/OCR 구조 정보를 더 잘 보존하는 전처리 개선은 일단 보류한다.

이 부분은 실제 문제 원본 구조를 더 봐야 하므로, 현재 단계에서는 규칙 예외 처리만 먼저 반영한다.

## 3. WEIRD_CHOICE 분석

v9 test 기준 팀원 생성 문제에서 `WEIRD_CHOICE`가 많이 발생했다.

```text
팀원 생성 test 선지: 530개
WEIRD_CHOICE 예측: 96개
실제 오류 라벨인 WEIRD_CHOICE 후보: 81개
라벨상 정상인데 WEIRD_CHOICE로 잡힌 후보: 15개
```

`WEIRD_CHOICE`는 명확한 규칙 오류 코드가 아니라, 모델이 지문/질문/선지를 함께 봤을 때 문제 맥락상 이상하다고 본 후보이다.

대표 패턴은 다음과 같다.

```text
지문 내용을 거의 그대로 반복하는 정답 선지
질문이 요구하는 답보다 너무 일반적인 선지
문장 끝이 부자연스러운 선지
예: ~이다, ~이었다, ~으로이다
문항의 대상과 선지의 설명 축이 어긋나는 경우
정답 선지가 설명이라기보다 지문 요약처럼 보이는 경우
순서형 문제에서 선지 자체가 너무 노출적인 경우
```

예시:

```text
지문: 별무반 편성 설명
선지: 말을 가진 사람을 폭넓게 편입하였다.
분석: 지문에 이미 핵심 단서가 직접적으로 들어 있어 정답 선지가 너무 노출적이다.

지문: 광복군 창설 설명
선지: 충칭에서 창설되어 광복군이라는 약칭을 갖게 되었다.
분석: 지문 내용을 거의 그대로 반복한다.

선지: 1405년 태종 때 이궁으로 처음 세워졌고이다.
분석: 문장 형식이 부자연스럽고 비문에 가깝다.
```

따라서 `WEIRD_CHOICE`는 무조건 폐기라기보다 사람이 직접 확인해서 다음 중 하나로 재분류하는 것이 좋다.

```text
ANSWER_IN_PASSAGE
ANSWER_LENGTH_BIAS
CHOICE_FORMAT_ERROR
실제 정상
기타 신규 오류 코드
```

## 4. 정답 선지에 오류가 몰리는 이유

현재 오류 라벨은 정답 선지에 많이 몰려 있다.

v9 전체 생성 데이터 기준:

```text
정답 선지 오류: 501개
오답 선지 오류: 130개
```

오류 코드별로 보면:

```text
정답 선지 오류
- ANSWER_IN_PASSAGE: 368개
- ANSWER_LENGTH_BIAS: 153개
- CHOICE_FORMAT_ERROR: 54개
- QUESTION_MARKER_MISMATCH: 2개

오답 선지 오류
- CHOICE_FORMAT_ERROR: 130개
```

이렇게 된 이유는 현재 확보된 오류 데이터가 `정답 선지 노출`, `정답 길이 편향`처럼 정답 선지에서 주로 발생하는 오류에 많이 치우쳐 있기 때문이다.

## 5. 오답 선지 오류도 잡아야 하는가?

잡아야 한다.

오답 선지도 다음 경우에는 오류 선지로 봐야 한다.

```text
오답 선지가 문장 형식상 깨짐
오답 선지가 너무 비상식적이거나 문제 품질을 떨어뜨림
오답 선지가 실제로는 정답처럼 보임
오답 선지가 다른 선지와 중복되거나 너무 유사함
오답 선지가 지문/질문 조건과 맞지 않는 형식으로 작성됨
오답 선지에 메타 표현, 풀이 문장, 생성 흔적이 들어감
```

현재 모델도 오답 선지 오류를 아예 못 잡는 것은 아니다.

v9 test 기준:

```text
팀원 생성 오답 선지 실제 오류: 18개
모델이 오류로 판단한 오답 선지: 19개
```

다만 오답 선지 오류 라벨이 대부분 `CHOICE_FORMAT_ERROR`에 한정되어 있어, 다양한 오답 오류를 학습하기에는 데이터가 부족하다.

## 6. 다음 데이터 보강 방향

오답 선지까지 제대로 검수하려면 팀원 생성 문제에서 오답 선지 오류를 더 라벨링해야 한다.

추천 라벨링 항목:

```text
DISTRACTOR_FORMAT_ERROR
오답 선지 문장/형식 오류

DISTRACTOR_TOO_WEIRD
오답 선지가 너무 뜬금없거나 품질이 낮음

DISTRACTOR_TOO_EASY
오답 선지가 너무 명백하게 틀려 변별력이 없음

DISTRACTOR_DUPLICATE
다른 선지와 중복되거나 거의 같음

DISTRACTOR_ACTUALLY_CORRECT
오답 선지가 사실상 정답 후보가 됨
```

현재 이 프로젝트의 출력은 여전히 이진 분류로 유지한다.

```text
0 = 오류 있음
1 = 오류 없음
```

다만 오류 사유를 기록할 때 정답 선지 오류와 오답 선지 오류를 구분해서 기록하면 다음 학습 성능 개선에 도움이 된다.
