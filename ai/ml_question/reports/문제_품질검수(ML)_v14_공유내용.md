# 선지 단위 2차 검수 모델 공유 문서 v14

## 1. 목적

이 모델은 문제 생성 후 바로 배포하기 전에, 생성된 문제의 **선지 단위 오류 후보를 2차로 걸러내는 보조 검수 모델**입니다.

자동으로 문제를 폐기하는 모델이 아니라, 팀원이 먼저 확인해야 할 선지를 골라주는 모델입니다.

즉, 모델의 목적은 다음과 같습니다.

- 생성된 문제에서 이상 가능성이 높은 선지를 빠르게 찾는다.
- 오류가 의심되는 이유를 오류 코드로 함께 제공한다.
- 사람이 모든 문제를 처음부터 보는 부담을 줄인다.
- 최종 판단은 사람이 한다.

## 2. 모델이 보는 입력 데이터

모델은 문항 전체를 한 번에 보는 것이 아니라, **선지 1개씩** 검사합니다.

입력 데이터는 다음 4개입니다.

```text
지문
질문
선지 1개
정답 여부
```

예시는 다음과 같습니다.

```text
지문: 세종 때 훈민정음이 창제되었다...
질문: 다음 자료에 대한 설명으로 옳은 것은?
선지: 간송미술관 소장본이 대표적이다.
정답 여부: 정답
```

5지선다 문항 1개는 모델 입장에서는 선지 5개로 나뉩니다.

```text
문항 1개
→ 선지 5개
→ 모델 입력 row 5개
```

## 3. y값

학습의 정답값은 이진 분류입니다.

```text
label = 0
오류 있음

label = 1
오류 없음
```

모델은 선지가 이상한지 아닌지를 판단합니다.

모델이 문제의 정답 번호를 맞히는 구조가 아닙니다.

## 4. 사용한 데이터

데이터는 크게 두 종류를 사용했습니다.

```text
기출 문제 데이터
→ 정상 선지 데이터로 사용

팀원이 생성한 문제 데이터
→ 오류가 포함된 생성 문제 데이터로 사용
```

주의할 점은, 팀원이 준 문제가 문항 단위로 실패 데이터라고 해도 선지 5개가 모두 오류라는 뜻은 아닙니다.

예를 들어 한 문항이 실패한 이유가 "정답 선지가 지문에 노출됨"이라면, 실제 오류 선지는 정답 선지 1개일 수 있습니다.

```text
문항 단위: 사용 불가 문항
선지 단위: 오류 선지 1개 + 정상 선지 4개일 수 있음
```

## 5. v14 테스트 결과 요약

v14 테스트셋 전체는 선지 기준 2065개입니다.

```text
전체 테스트 선지: 2065개
정상 선지: 1948개
오류 선지: 117개
```

팀원 생성 데이터는 테스트셋에 선지 기준 530개 들어갔습니다.

```text
팀원 생성 선지: 530개
5지선다 기준 약 106문항
```

최종 검수 결과는 다음과 같습니다.

```text
검수필요: 119개
참고검수: 11개
통과: 1935개
```

성능을 쉽게 정리하면 다음과 같습니다.

```text
실제 오류 선지 117개 중 109개 탐지
실제 오류 선지 8개 미탐

정상 선지 1948개 중 21개 오탐
정상 선지 1927개 정상 통과
```

즉, 현재 모델은 오류 선지를 대부분 잡고, 정상 선지는 대부분 통과시킵니다.

## 6. 오류 코드 설명

결과 파일에는 오류가 의심되는 이유가 오류 코드로 표시됩니다.

| 오류 코드 | 의미 | 확인 방법 |
|---|---|---|
| `ANSWER_LENGTH_BIAS` | 정답 선지가 다른 선지보다 유독 길거나 짧음 | 선지 길이, 다른 선지 평균 길이 확인 |
| `ANSWER_RESTATEMENT_SUSPECT` | 정답 선지가 지문 내용을 거의 다시 말한 것으로 의심됨 | 지문과 정답 선지 표현 비교 |
| `CHOICE_FORMAT_ERROR` | 선지 문장이나 표현이 어색함 | 문장 종결, 조사, 생성문 오류 확인 |
| `ORDER_CHOICE_CONTEXT_REQUIRED` | `(가)-(나)-(다)` 같은 순서형 선지라 문항 전체 확인 필요 | 지문, 질문, 선지 5개를 함께 확인 |
| `ODD_DISTRACTOR` | 오답 선지가 너무 어색하거나 쉽게 제거될 가능성 있음 | 오답 선지가 자연스러운 한국사 선지인지 확인 |
| `ANSWER_IN_PASSAGE` | 정답 선지가 지문에 직접 노출됨 | 지문에 정답 표현이 그대로 있는지 확인 |
| `QUESTION_CHOICE_MISMATCH` | 질문과 선지 형식이 맞지 않는 의심 | 참고용 코드로만 사용 |

## 7. QUESTION_CHOICE_MISMATCH 처리 방식

`QUESTION_CHOICE_MISMATCH`는 v14에서 **참고코드**로 분리했습니다.

이 코드는 오탐이 많았기 때문에, 이 코드 하나만으로는 자동으로 `검수필요` 처리하지 않습니다.

```text
QUESTION_CHOICE_MISMATCH만 있음
→ 참고코드로만 표시
→ 자동 오류 판정 X

모델도 오류라고 판단하거나 다른 오류 코드와 함께 있음
→ 검수필요 가능
```

그래서 팀원은 이 코드를 보면 "질문과 선지가 살짝 안 맞을 수도 있구나" 정도로 참고하면 됩니다.

## 8. 팀원이 확인해야 할 파일

가장 중요한 파일은 다음입니다.

```text
test_review.csv
```

이 파일이 실제 검수용 메인 파일입니다.

우선 확인할 컬럼은 다음과 같습니다.

```text
검수상태
오류확률
오류코드
참고코드
지문
질문
선지
```

상세 분석이 필요하면 다음 파일을 봅니다.

```text
test_predictions.csv
```

이 파일에는 모델 예측값, 실제 라벨, 최종 판정, 규칙 코드가 더 자세히 들어 있습니다.

오류 코드별 개수를 보고 싶으면 다음 파일을 봅니다.

```text
test_error_code_summary.csv
```

## 9. 검수상태별 확인 방법

### 검수필요

가장 먼저 확인해야 하는 선지입니다.

모델이 오류 가능성이 높다고 본 선지입니다.

```text
검수필요
→ 반드시 사람이 확인
→ 실제 오류면 문제 수정 또는 선지 교체
```

### 참고검수

규칙상 확인해볼 만한 선지입니다.

모델이 강하게 오류라고 본 것은 아니지만, 사람이 한 번 보면 좋습니다.

```text
참고검수
→ 시간이 있으면 확인
→ 반복적으로 같은 문제가 나오면 생성 로직 개선
```

### 통과

모델과 규칙 모두 큰 이상을 찾지 못한 선지입니다.

```text
통과
→ 기본적으로 통과
→ 단, 최종 제출 전 샘플링 검수는 권장
```

## 10. 팀원이 실제로 사용하는 흐름

```text
1. 문제 생성
2. 생성 문제를 선지 단위로 전처리
3. v14 모델로 선지별 오류 여부 예측
4. test_review.csv 생성
5. 검수필요 선지 먼저 확인
6. 오류 코드에 따라 수정 방향 결정
7. 필요하면 참고검수까지 확인
8. 수정 후 재검수
```

## 11. 결과 해석 시 주의할 점

이 모델은 문항 단위 폐기 모델이 아닙니다.

선지 단위 검수 모델입니다.

따라서 "팀원이 준 1144문항이 실패 데이터인데 왜 오류가 100개 정도만 나오냐"는 질문은 다음처럼 이해해야 합니다.

```text
팀원 생성 문항 1144개 전체를 한 번에 평가한 결과가 아님
테스트셋에는 그중 일부만 들어감
현재 테스트셋의 팀원 생성 데이터는 선지 530개
선지 530개는 약 106문항에 해당
그중 오류 선지를 잡은 결과가 현재 수치
```

또한 한 문항이 사용 불가여도 선지 5개가 모두 오류인 것은 아닙니다.

```text
문항 1개가 실패
→ 실제 오류 선지는 정답 선지 1개일 수 있음
→ 나머지 오답 4개는 정상일 수 있음
```

## 12. 최종 판단

v14는 현재까지 만든 버전 중 운영용 2차 검수에 가장 적합합니다.

사용 방향은 다음이 적절합니다.

```text
자동 폐기용 X
검수 후보 추출용 O
최종 판단은 사람 O
```

현재 모델은 다음을 잘 잡습니다.

- 정답 선지가 지문과 너무 가까운 경우
- 정답 선지가 다른 선지보다 길이상 튀는 경우
- 선지 문장이 생성문처럼 어색한 경우
- 순서형 선지처럼 문항 전체 확인이 필요한 경우
- 오답 선지가 너무 이상한 경우

아직 약한 부분은 다음입니다.

- 오답 선지의 미세한 문장 오류
- 역사적 사실성 자체 검증
- 사람 기준으로만 알 수 있는 미묘한 부적절성

따라서 v14는 팀원이 생성한 문제를 바로 통과시키기 전에 사용하는 **2차 안전 검수 모델**로 활용하면 됩니다.
