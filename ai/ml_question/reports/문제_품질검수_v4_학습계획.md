# 문제 2차 검수 모델 v4 학습 계획

## 1. 목적

문제 생성 팀원이 만든 한국사 객관식 문항을 한 번 더 검수하는 2차 보안 모델을 만든다.

이 모델은 정답 번호를 맞히는 모델이 아니다. 이미 주어진 정답 여부를 입력으로 사용하고, 해당 선지가 문제 품질 관점에서 이상한지 판단한다.

최종 목적은 다음과 같다.

- 정답 선지가 지문에 너무 직접적으로 노출된 문제 탐지
- 선지 문장/형식이 이상한 문제 탐지
- 중복 선지 또는 복수 정답 가능성이 있는 문제 탐지
- 발문과 선지 또는 지문이 맞지 않는 문제 탐지
- 문제 생성 결과를 서비스에 넣기 전에 2차로 걸러내기

## 2. Input 데이터

모델 입력은 선지 1개 단위로 만든다.

```text
input X = 지문 + 질문 + 선지 1개 + 정답 여부
```

예시:

```text
[지문]
...

[질문]
다음 자료에 대한 설명으로 옳은 것은?

[선지]
간송미술관 소장본이 대표적이다.

[정답 여부]
정답 선지
```

정답 여부를 input에 넣는 이유는 모델이 정답을 맞히게 하려는 것이 아니다.

정답 선지에서만 발생하는 오류가 있기 때문이다.

- 정답 선지가 지문에 노출됨
- 정답 선지만 길거나 짧음
- 정답 선지가 발문 조건과 맞지 않음

따라서 `is_answer`는 정답 예측 대상이 아니라 검수 판단을 돕는 입력 feature다.

## 3. y값

학습 y값은 이진 라벨이다.

```text
y = label
```

라벨 의미:

```text
label = 0 -> 이상 있음
label = 1 -> 이상 없음
```

따라서 BERT 모델은 이진 분류 모델이다.

`error_codes`는 y가 아니라 보조 정보다.

```text
main y = label
sub info = error_codes
```

오류 코드는 다음 용도로 사용한다.

- 학습 데이터에서 왜 이상인지 확인
- 평가 결과 CSV에서 정답 오류 사유 참고
- 운영 시 규칙 기반 후처리로 예상 오류 코드 표시
- 나중에 오류 유형 분류 모델을 따로 만들 때 확장 가능

## 4. 사용하는 오류 코드

v4에서 BERT 학습에 사용하는 오류 코드는 다음과 같다.

| 오류 코드 | 한글 의미 |
|---|---|
| `ANSWER_IN_PASSAGE` | 정답 사실이 지문/질문에 노출됨 |
| `ANSWER_LENGTH_BIAS` | 정답 선지 길이 편향 |
| `CHOICE_FORMAT_ERROR` | 선지 형식/문장 완결성 오류 |
| `DUPLICATE_OR_SIMILAR_CHOICE` | 중복 또는 유사 선지 |
| `NO_OR_MULTI_ANSWER` | 정답이 없거나 복수 정답 가능 |
| `QUESTION_FORMAT_ERROR` | 발문/표식 형식 오류 |
| `QUESTION_CHOICE_MISMATCH` | 발문·지문·정답축 불일치 |
| `WEIRD_CHOICE` | 시험 문항 품질 부족 또는 부적절 선지 |

역사적 사실성 자체를 확인해야 하는 오류는 이번 BERT 학습에서 제외한다.


train/test 분리는 문항 단위로 한다.

같은 문항의 5개 선지가 train과 test에 나뉘면 성능이 실제보다 좋게 보일 수 있기 때문이다.

## 8. 평가 기준

accuracy만 보면 안 된다.

이 작업에서 중요한 것은 이상 선지를 놓치지 않는 것이다.

중요한 지표:

- abnormal recall
- abnormal precision
- abnormal f1
- confusion matrix

특히 `abnormal_recall`이 낮으면 실제 오류를 못 잡는다는 뜻이므로 실패로 본다.

오류 코드별 성능은 이번 이진 분류 모델의 직접 평가지표가 아니다. `error_codes`는 보조 설명값이므로, 모델 평가는 `label=0/1` 기준으로 본다.

## 9. 왜 이걸 하는가

생성 모델이 만든 문제는 겉보기에는 정상처럼 보일 수 있다.

하지만 실제로는 다음 문제가 생길 수 있다.

- 정답이 지문에 이미 들어 있음
- 정답 선지만 너무 티가 남
- 오답 선지가 너무 이상함
- 선지가 중복되어 복수 정답처럼 보임
- 질문이 요구하는 축과 정답 선지가 맞지 않음

이런 문제를 사람이 전부 검수하기 어렵기 때문에 BERT 계열 모델을 2차 필터로 둔다.

운영에서는 모델 결과와 규칙 검사를 함께 사용한다.

```text
규칙 검사 + BERT 오류 코드 예측 -> 최종 2차 검수 결과
```

## 10. 운영 방향: 문항 폐기보다 선지 교체

최종 운영은 문항 전체를 바로 폐기하기보다, 먼저 이상 선지를 찾아 교체 대상으로 보내는 방향이 좋다.

권장 흐름:

```text
문항 생성
-> 선지 5개를 각각 BERT 이진 분류
-> label=0으로 나온 선지 번호 확인
-> 해당 선지만 재생성 또는 수정
-> 수정된 5지선다 문항을 다시 전체 검수
```

단, 선지를 단순 삭제하면 5지선다 구조가 깨지므로 실제 운영명은 `선지 폐기`보다 `선지 교체/재생성`이 더 정확하다.

운영 판정은 다음처럼 나눈다.

```text
모든 선지 label=1
-> 사용 가능 후보

일부 선지 label=0
-> 문항 보류, 이상 선지 교체

정답 없음/복수 정답/중복 선지
-> 선지 교체 후 문항 전체 재검수

RunPod 생성 실패/근거 추적 부족/난이도 메타데이터 누락
-> BERT 판단 대상이 아니라 파이프라인 규칙에서 처리
```

그래서 v4 노트북은 다음 결과 파일을 저장한다.

```text
choice_quality_output_v5/

test_predictions.csv
-> 선지 단위 예측 결과

test_question_predictions.csv
-> 문항 단위 요약과 교체 대상 선지 번호

threshold_report.csv
-> threshold별 선지 단위/문항 단위 성능 비교
```
