# 평가지표 v7 - KLUE/RoBERTa v2 Early Stopping 실험 계획

## 목적

`klue_roberta_v1`은 최대 3 epoch를 고정으로 학습했습니다.
이번 v2에서는 class weight는 아직 적용하지 않고, 기존 학습 파라미터를 유지한 상태에서 validation loss 기반 early stopping만 추가합니다.
즉, 성능 개선 요인을 한 번에 섞지 않고 early stopping 효과만 먼저 확인합니다.

## 변경 사항

- 노트북: `klue_roberta_v2.ipynb`
- 모델: `klue/roberta-base`
- 입력 데이터: `split_v1/train_features_v1.json`, `split_v1/predict_input_v1.json`, `split_v1/test_answer_v1.json`
- 대상 모델: `era`, `topic`, `question_type` 각각 별도 학습
- class weight: 미적용
- 추가 기능: train 데이터 내부에서 validation set을 분리하고 validation loss를 기준으로 early stopping 적용
- 추가 확인: target별 train loss / validation loss 그래프 출력 및 PNG 저장

## 설정

| 항목 | 값 | 의미 |
|---|---:|---|
| `MAX_LENGTH` | 256 | 문제 텍스트 토큰 최대 길이 | 
| `MAX_EPOCHS` | 3 | v1과 동일한 최대 반복 횟수 | 
| `BATCH_SIZE` | 8 | GPU 메모리를 고려한 1회 학습 묶음 크기 | 
| `LEARNING_RATE` | 2e-5 | KLUE/RoBERTa fine-tuning 기본 시작값 | 
| `VALID_SIZE` | 0.2 | train 데이터 중 20%를 validation으로 사용 | 
| `PATIENCE` | 1 | validation loss가 1 epoch라도 개선되지 않으면 중단 | 
| `MIN_DELTA` | 0.0 | validation loss가 조금이라도 낮아지면 개선으로 판단 | 

## 데이터 사용 방식

v2에서도 71~78회차는 최종 평가용으로 유지합니다.
다만 early stopping을 위해 47~70회차 train 데이터 안에서 다시 train/validation을 나눕니다.

```text
47~70회차 train_features_v1
  -> fit set: 실제 모델 학습
  -> validation set: epoch마다 손실 확인, early stopping 판단

71~78회차 predict_input_v1
  -> 라벨 없이 예측 입력으로 사용

71~78회차 test_answer_v1
  -> 예측 후 정답 비교 및 평가 지표 계산
```

## Early Stopping 기준

epoch마다 다음 값을 확인합니다.

- train loss: 학습 데이터에서의 손실
- validation loss: 학습에 직접 사용하지 않은 검증 데이터에서의 손실

중단 판단은 train loss가 아니라 validation loss로 합니다.
train loss는 계속 낮아져도 모델이 과적합되면 validation loss가 증가할 수 있기 때문입니다.

## 확인할 지표

기본 비교 지표는 v1과 동일하게 유지하고, v2부터 클래스별 상세 지표를 함께 확인합니다.

- Accuracy
- Macro F1
- Weighted F1
- 클래스별 Precision
- 클래스별 Recall
- 클래스별 F1-score
- 클래스별 Support
- best epoch
- best validation loss
- epoch별 train loss / validation loss 변화

Confusion Matrix는 v2에는 추가하지 않습니다.
v3에서 class weight를 적용할 때 예측 쏠림이 어떻게 바뀌는지 함께 보기 위해 추가합니다.

## 기대 효과

early stopping은 데이터가 적을 때 특히 유용할 수 있습니다.
고정 epoch 학습보다 과적합을 줄이고, 가장 validation loss가 낮았던 시점의 모델을 사용하게 됩니다.

다만 topic처럼 클래스 분포가 불균형한 항목은 early stopping만으로 충분히 개선되지 않을 수 있습니다.
v2 결과 확인 후 다음 실험에서 class weight 적용 여부를 판단합니다.
