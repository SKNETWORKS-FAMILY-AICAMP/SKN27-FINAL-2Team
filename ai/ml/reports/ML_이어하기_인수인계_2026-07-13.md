## 1. 현재 ML 작업의 목적

현재 진행 중인 ML 작업은 한국사 기출문제 데이터를 이용해 출제 경향을 분석하는 것이다.

최종 목적은 다음 두 가지이다.

1. 과거 기출문제를 학습하여 시대와 주제의 출제 경향을 파악한다.
2. 최신 회차에서 어떤 시대와 주제가 자주 나오는지 분석하여 문제 생성과 학습 계획 추천에 활용한다.

현재 ML은 서비스에 바로 반영하는 최종 단계가 아니라, 모델 성능과 데이터 라벨 기준을 검증하는 실험 단계이다.

## 2. 핵심 데이터

현재 사용하는 기본 데이터는 다음 파일이다.

- `ai/ml/ML_han_v1.json`
- `ai/ml/output/ml_han_features_v1.csv`

주요 feature 데이터는 `ML_han_v1.json`에서 생성되었다.

현재 모델 입력에는 다음 버전이 있다.

| 입력 버전 | 의미 |
|---|---|
| `text` | 문제 지문 중심 입력 |
| `text_with_choices` | 문제 지문 + 선택지 포함 입력 |
| `text_with_core` | 문제 지문 + 핵심 개념(core_concept) 포함 입력 |

오늘 실험 결과 기준으로는 `text_with_core`가 가장 좋은 방향이었다.

## 3. 라벨 구조

현재 주요 라벨은 세 가지이다.

| 라벨 | 의미 | 현재 판단 |
|---|---|---|
| `era` | 시대 | 성능이 비교적 안정적 |
| `topic` | 원래 주제 10개 | 성능이 낮음, 참고 지표로 유지 |
| `topic_train` | 통합 주제 5개 | 성능 개선 대상 |

`topic_train`은 실제 원래 주제를 없애는 것이 아니라, 모델 학습 성능을 보기 위해 만든 통합 주제이다.

현재 통합 주제는 다음 5개이다.

- 문화
- 사건
- 인물
- 정치
- 제도

주의할 점:

- 기존 라벨을 바로 바꾸지 않는다.
- 현재는 라벨 기준표를 재정의하고 오분류를 검토하는 단계이다.
- 사람이 검토한 결과는 `suggested_label` 등 별도 컬럼에 기록하고, 원본 라벨은 유지한다.

## 통합 주제 매핑

원래 주제(`topic`) 10개를 모델 학습 안정성을 위해 `topic_train` 5개로 통합했다.


주의: `topic_train`은 모델 성능 검증을 위한 학습용 통합 라벨이며, 원래 `topic` 라벨은 보존한다. 따라서 평가는 `topic_train` 기준 성능과 원래 `topic` 기준 성능을 함께 확인한다.

| 원래 주제(topic) | 통합 주제(topic_train) |
|---|---|
| 정치 | 정치 |
| 사회 | 정치 |
| 경제 | 정치 |
| 군사 | 정치 |
| 외교 | 정치 |
| 문화 | 문화 |
| 사상·종교 | 문화 |
| 사건 | 사건 |
| 인물 | 인물 |
| 제도 | 제도 |


## 4. 평가 split

현재 평가 split은 크게 두 종류이다.

### 4.1 모델 자체 분류 성능 평가

사용 split:

- `split_era_topic_train_stratified_v1`

의미:

- 시대 + 통합 주제 조합을 고려해서 train/test를 나눈다.
- 모델이 전체 데이터 분포 안에서 라벨을 잘 구분하는지 확인한다.

현재 주요 실험은 대부분 이 split 기준으로 진행했다.

### 4.2 최신 회차 평가

사용 split:

- `split_time_v1`

의미:

- 70회차까지 학습한다.
- 71~78회차를 평가한다.
- 최신 회차 경향을 얼마나 잘 맞히는지 확인한다.

주의:

- 이 평가는 모델 자체의 일반 분류 성능이라기보다 최신 회차 재현성 확인에 가깝다.
- `topic_train`은 최신 회차 평가에서 성능이 크게 낮아졌다.

## 6. 좋아졌던 작업

### 6.1 core_concept 추가

`text_with_core`를 사용했을 때 성능이 가장 의미 있게 좋아졌다.

이유:

- 주제 분류에 필요한 핵심 단서를 모델 입력에 직접 제공한다.
- 문제 지문만으로 애매한 주제 판단을 보완할 수 있다.

### 6.2 learning rate 낮추기

`learning_rate=5e-6` 조합이 좋은 결과를 냈다.

이유:

- KLUE/RoBERTa-base를 작은 데이터셋에서 파인튜닝할 때 너무 큰 learning rate는 불안정할 수 있다.
- 낮은 learning rate가 더 안정적인 업데이트를 만든 것으로 보인다.

### 6.3 batch size 16

`batch_size=16` 조합에서 현재 최고 결과가 나왔다.

주의:

- GPU 메모리가 부족하면 batch size를 다시 8로 낮춰야 한다.
- RunPod에서 여러 커널이 동시에 떠 있으면 OOM이 발생한다.

판단:

- 긴 지문에서 주제 판단에 필요한 단서가 잘릴 수 있다.
- 현재는 `max_length=512` 유지가 더 낫다.

### 7.3 원래 주제 10개 예측

`topic` 원래 주제 10개 예측은 성능이 낮았다.

성능:

| accuracy | 0.5810 |

판단:

- 데이터가 적은 주제 라벨에서 성능이 크게 떨어진다.
- 원래 주제는 완전히 버리지 말고 참고 지표로 유지한다.
- 모델 성능 개선은 우선 `topic_train` 기준으로 진행한다.

## 13. RunPod 실행 시 주의점

RunPod에서 OOM이 발생한 적이 있다.

원인:

- 여러 Jupyter kernel이 동시에 떠 있었다.
- 각 kernel이 GPU 메모리를 일부 점유했다.

해결 방법:

1. Jupyter 왼쪽 사이드바에서 Running Terminals and Kernels 확인
2. 사용하지 않는 kernel shutdown
3. 필요하면 RunPod pod 재시작
4. 그래도 OOM이면 batch size를 16에서 8로 낮춤
