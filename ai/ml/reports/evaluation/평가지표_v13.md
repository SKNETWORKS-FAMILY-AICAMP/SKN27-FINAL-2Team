# KLUE/RoBERTa v5 실험 준비 기록

## 1. 작업 목적

v5는 새 노트북 파일을 추가하지 않고, 기존 `klue_roberta_v4.ipynb`를 그대로 사용해서 실행합니다.
대신 노트북 생성 코드인 `make_klue_roberta_v4_notebook.py`의 설정을 v5 실험용으로 변경했습니다.

이번 실험은 v4 구조를 유지한 상태에서 `MAX_LENGTH`만 변경하여, 긴 문제 지문을 더 많이 반영했을 때 성능이 좋아지는지 확인하는 목적입니다.

## 2. v5 변경 사항

| 항목 | v4 | v5 |
|---|---:|---:|
| 노트북 파일 | `klue_roberta_v4.ipynb` | `klue_roberta_v4.ipynb` |
| 결과 저장 폴더 | `klue_roberta_v4` | `klue_roberta_v5` |
| `MAX_LENGTH` | 384 | 512 |
| `MAX_EPOCHS` | 8 | 8 |
| `BATCH_SIZE` | 8 | 8 |
| `LEARNING_RATE` | 2e-5 | 2e-5 |
| `PATIENCE` | 2 | 2 |
| class weight | 적용 | 적용 |
| Stratified K-Fold | 3-fold | 3-fold |
| Confusion Matrix | 생성 | 생성 |
| Loss graph | 생성 | 생성 |

## 3. 변경 이유

`MAX_LENGTH`는 KLUE/RoBERTa가 한 번에 읽는 토큰 길이입니다.
기존 v4의 384는 v1~v3보다 긴 지문을 더 많이 담기 위한 설정이었고, v5에서는 이를 512까지 늘려 문제 본문과 자료 설명이 잘리는 양을 더 줄입니다.

다른 파라미터는 유지했습니다.
이유는 한 번에 여러 조건을 바꾸면 어떤 변경이 성능에 영향을 줬는지 판단하기 어렵기 때문입니다.
따라서 v5는 `MAX_LENGTH` 변경 효과만 확인하는 실험입니다.

## 4. 실행 후 확인할 평가 항목

각 target별로 아래 항목을 확인합니다.

```text
accuracy: 0.xxxx
precision: 0.xxxx
recall: 0.xxxx
f1-score: 0.xxxx
macro f1: 0.xxxx
Weighted F1: 0.xxxx
Confusion Matrix: *_klue_roberta_v5_confusion_matrix.png
```

확인 대상 target:

- `era`
- `topic`
- `question_type`

## 5. 예상 리스크

`MAX_LENGTH=512`는 입력 길이가 늘어나기 때문에 v4보다 학습 시간이 길어질 수 있습니다.
Colab T4 GPU에서는 `BATCH_SIZE=8`로 실행 가능할 가능성이 높지만, 메모리 오류가 발생하면 `BATCH_SIZE=4`로 낮춰야 합니다.

단, 메모리 오류가 없다면 이번 v5에서는 `BATCH_SIZE`를 바꾸지 않고 그대로 진행합니다.

## 7. 현재 상태

v5 노트북을 새로 만들지 않았습니다.
기존 `klue_roberta_v4.ipynb`를 다시 생성했고, 내부 설정과 결과 저장 경로만 v5로 변경했습니다.

따라서 Colab에서는 기존처럼 `klue_roberta_v4.ipynb`를 업로드하거나 열어서 실행하면 됩니다.
실행 결과는 `Final_project/common/klue_roberta_v5` 폴더에 저장됩니다.
