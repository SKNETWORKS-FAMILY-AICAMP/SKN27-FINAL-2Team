# 평가지표 v3

## 1. 변경 목적

v2까지는 시간순 평가를 기준으로 baseline 성능을 확인했다.

```text
train: 47~70회
test: 71~78회
```

하지만 피드백에 “평가 데이터는 층화추출로 나누는 것이 좋다”는 내용이 있어, 보조 평가로 층화추출 baseline을 추가한다.

## 2. 평가 방식 구분

| 평가 방식 | 목적 | 장점 | 주의점 |
|---|---|---|---|
| 시간순 평가 | 과거 기출로 최신 기출에 적용 가능한지 확인 | 프로젝트 목적과 잘 맞음 | train/test 라벨 분포가 달라질 수 있음 |
| 층화추출 평가 | 라벨 비율을 맞춘 상태에서 모델 자체 분류 성능 확인 | 인밸런스에 의한 평가 왜곡 완화 | 최신 회차 예측 관점에서는 데이터 누수 가능 |

따라서 최종 해석에서는 다음처럼 구분한다.

```text
메인 평가: 시간순 평가
보조 평가: 층화추출 평가
```

## 4. 층화추출 설계

처음에는 `era + topic + question_type` 조합으로 층화추출을 고려했다.
하지만 전체 데이터에서 조합 라벨은 singleton이 많아 안정적인 stratified split에 적합하지 않았다.

확인 결과:

| stratify key | 클래스 수 | 최소 건수 | singleton |
|---|---:|---:|---:|
| era | 10 | 27 | 0 |
| topic | 10 | 26 | 0 |
| question_type | 5 | 13 | 0 |
| era + topic | 89 | 1 | 10 |
| era + topic + question_type | 199 | 1 | 47 |

따라서 각 모델의 target에 맞춰 층화 기준을 다르게 둔다.

| 모델 | stratify 기준 |
|---|---|
| era 모델 | `era` |
| topic 모델 | `topic` |
| question_type 모델 | `question_type` |

## 6. 기대하는 확인 포인트

1. 시간순 평가에서 낮았던 `topic` 성능이 층화추출에서는 개선되는지 확인한다.
2. 층화추출에서도 `topic` 성능이 낮으면 라벨 기준 또는 입력 피처 자체의 문제일 가능성이 크다.
3. `question_type`은 Accuracy와 Macro F1 차이가 여전히 큰지 확인한다.
4. `era`는 시간순 평가와 층화추출 평가 모두 안정적인지 비교한다.
