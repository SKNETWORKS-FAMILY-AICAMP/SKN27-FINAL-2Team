## Loss 해석

세 target 모두 best epoch가 3입니다.
즉, `MAX_EPOCHS = 3` 안에서는 validation loss가 계속 개선되었고 early stopping으로 중간 종료되지는 않았습니다.

### era

- train loss: 2.0138 -> 1.3455 -> 0.9800
- validation loss: 1.5796 -> 1.2372 -> 1.1557
- v2 대비 Macro F1이 크게 상승했습니다.
- class weight가 시대 소수 클래스 성능 개선에 긍정적으로 작용한 것으로 보입니다.

### topic

- train loss: 2.2212 -> 1.8633 -> 1.4203
- validation loss: 2.0103 -> 1.7226 -> 1.6303
- Accuracy는 하락했지만 Macro F1은 상승했습니다.
- 소수 주제를 더 예측하려는 방향으로 바뀌었으나, 여전히 경제/군사/외교 등 일부 클래스는 제대로 잡지 못합니다.

### question_type

- train loss: 1.5612 -> 0.9597 -> 0.4568
- validation loss: 1.2856 -> 0.5417 -> 0.4883
- v2 대비 Accuracy, Macro F1, Weighted F1이 모두 하락했습니다.
- class weight가 `연대기의 파악` 쪽 예측을 크게 늘리면서 다수 클래스인 `역사 자료의 분석 및 해석` 성능이 많이 줄었습니다.

## Confusion Matrix 해석

### era

대각선 값이 비교적 잘 유지됩니다.
특히 고조선, 선사 시대처럼 데이터가 적은 클래스도 일부 맞추고 있습니다.
다만 남북국 시대는 고려/일제 강점기/조선 등으로 분산되어 아직 불안정합니다.

### topic

v2보다 예측 클래스가 넓어졌지만, 경제/군사/외교는 여전히 거의 맞추지 못합니다.
정치와 인물은 서로 많이 혼동되고, 사건도 정치/인물 쪽으로 흘러갑니다.
topic은 class weight만으로는 충분하지 않고, max_length 증가나 학습 epoch 증가를 같이 확인할 필요가 있습니다.

### question_type

`연대기의 파악` recall은 좋아졌지만, `역사 자료의 분석 및 해석`이 다른 유형으로 많이 분산되었습니다.
class weight가 과하게 작동한 것으로 볼 수 있습니다.
question_type은 class weight를 그대로 쓰기보다 가중치 완화, 유형 재정의, 또는 별도 튜닝이 필요합니다.

## 특이 사항

이번 결과 JSON에는 `class_weights` 값 자체가 target 결과에 저장되어 있지 않습니다.
예측 분포와 top-level 설정은 v3 실험 결과로 해석할 수 있지만, class weight 값 표까지 남기려면 최신 `klue_roberta_v3.ipynb`로 target 학습 셀부터 다시 실행해야 합니다.

## 결론

v3 class weight는 `era`, `topic`에는 긍정적인 효과가 있었습니다.
특히 Macro F1 기준으로 보면 era는 큰 폭으로 개선되었고 topic도 소폭 개선되었습니다.

반면 `question_type`은 성능이 하락했습니다.
따라서 다음 v4에서 max_length 증가, epoch 증가, cross validation을 확인하되, question_type은 class weight 강도를 조정하는 후속 실험도 고려해야 합니다.
