# 평가지표 v9 - KLUE/RoBERTa v3 Class Weight 실험 계획

## 목적

v2에서는 validation loss, early stopping, loss graph를 추가했지만 class weight는 적용하지 않았습니다.
v3에서는 v2 구조를 유지하면서 class weight와 confusion matrix를 추가합니다.

핵심 확인 목표는 소수 클래스의 recall과 macro_f1이 개선되는지 확인하는 것입니다.

## 변경 사항

- 노트북: `klue_roberta_v3.ipynb`
- 생성 스크립트: `make_klue_roberta_v3_notebook.py`
- 모델: `klue/roberta-base`
- 대상: `era`, `topic`, `question_type` 각각 별도 학습
- 유지: validation loss, early stopping, loss graph, 클래스별 precision/recall/f1-score
- 추가: class weight 적용
- 추가: confusion matrix 출력 및 PNG 저장

## Class Weight 적용 방식

Hugging Face 기본 loss를 그대로 쓰지 않고, 학습 루프에서 직접 weighted loss를 계산합니다.

```python
loss_fn = torch.nn.CrossEntropyLoss(weight=class_weights)
loss = loss_fn(outputs.logits, labels)
```

class weight는 fit 데이터의 클래스 분포를 기준으로 계산합니다.
데이터가 적은 클래스일수록 loss에 더 큰 가중치를 주어, 모델이 다수 클래스만 맞추는 방향으로 치우치는 것을 줄입니다.

## Confusion Matrix 추가 이유

class weight를 적용하면 예측 분포가 바뀔 수 있습니다.
따라서 단순히 macro_f1만 보는 것이 아니라, 실제 클래스가 어떤 클래스로 잘못 예측되는지 함께 확인합니다.

특히 다음을 확인합니다.

- 소수 클래스가 여전히 다수 클래스로 몰리는지
- class weight 적용 후 소수 클래스 예측 수가 늘어나는지
- 다수 클래스 성능이 과하게 떨어지는지
- topic과 question_type에서 recall 0인 클래스가 줄어드는지

## v2 대비 판단 기준

v3가 성공적이라고 판단하려면 다음 중 일부가 확인되어야 합니다.

- topic macro_f1 상승
- question_type macro_f1 상승
- recall 0인 소수 클래스 감소
- confusion matrix에서 다수 클래스로만 몰리는 현상 완화

단, class weight는 소수 클래스 예측을 늘리는 대신 전체 accuracy나 weighted_f1을 낮출 수 있습니다.
따라서 v3는 accuracy만으로 판단하지 않고 macro_f1과 클래스별 recall을 중심으로 봅니다.
