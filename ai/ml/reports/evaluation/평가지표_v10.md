# 평가지표 v10 - KLUE/RoBERTa v4 Cross Validation 실험 계획

## 목적

v4에서는 v3의 class weight를 유지하고, 문제 지문 길이와 학습 반복 수를 조정합니다.
또한 단일 validation split 대신 stratified k-fold cross validation을 사용해 train 구간 내부 평가 안정성을 확인합니다.

## 변경 사항

- 노트북: `klue_roberta_v4.ipynb`
- 생성 스크립트: `make_klue_roberta_v4_notebook.py`
- 모델: `klue/roberta-base`
- class weight: 적용
- confusion matrix: 적용
- loss graph: 적용
- `MAX_LENGTH`: 256 -> 384
- `MAX_EPOCHS`: 3 -> 8
- `PATIENCE`: 1 -> 2
- validation 방식: 단일 split -> `3-fold StratifiedKFold`

## 실험 구조

v4는 target별로 다음 순서로 진행합니다.

```text
1. 47~70회차 train 데이터에서 3-fold stratified cross validation 수행
2. fold마다 validation loss 기준 early stopping 수행
3. fold별 best epoch와 validation 성능 기록
4. fold별 best epoch 평균을 final_epochs로 결정
5. 47~70회차 전체 train 데이터로 final_epochs만큼 재학습
6. 71~78회차 predict_input_v1 예측
7. test_answer_v1로 최종 평가
```

## 설정

| 항목 | 값 | 변경 이유 |
|---|---:|---|
| `MAX_LENGTH` | 384 | 긴 사료형 문제 지문이 256에서 잘릴 가능성 완화 |
| `MAX_EPOCHS` | 8 | early stopping이 있으므로 충분한 학습 기회 제공 |
| `PATIENCE` | 2 | epoch를 늘렸으므로 1회 흔들림으로 바로 중단하지 않음 |
| `N_SPLITS` | 3 | Colab 학습 시간을 고려한 cross validation 시작값 |
| `BATCH_SIZE` | 8 | v1~v3과 동일 |
| `LEARNING_RATE` | 2e-5 | v1~v3과 동일 |

## v3 오류 반영 사항

v3 진행 중 확인된 오류를 v4에 반영했습니다.

- 결과 폴더가 없을 때 `plt.savefig()`에서 `FileNotFoundError`가 발생하지 않도록 그래프 저장 전에 `RESULT_DIR.mkdir(parents=True, exist_ok=True)` 실행
- Confusion Matrix 한글 라벨이 깨지지 않도록 `koreanize-matplotlib` 적용
- `koreanize-matplotlib`이 동작하지 않는 환경을 대비해 `NanumGothic` fallback 설정
- `confusion_matrix`가 결과 객체에 없더라도 `row_predictions`가 있으면 다시 계산할 수 있도록 방어 처리

## 판단 기준

v4에서는 두 가지를 분리해서 봅니다.

1. cross validation 평균 성능
   - train 구간 내부에서 모델이 안정적으로 학습되는지 확인합니다.

2. 71~78회차 최종 성능
   - 최신 회차에 대해 실제 추세 예측 성능이 개선되는지 확인합니다.

v4는 여러 조건을 동시에 바꾸는 실험입니다.
따라서 v3보다 좋아지거나 나빠지더라도 원인을 하나로 단정하지 않고, `max_length`, `epoch`, `cross validation`을 함께 적용한 종합 실험으로 기록합니다.
