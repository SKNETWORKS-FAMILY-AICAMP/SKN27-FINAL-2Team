# 지문 평가 구조

지문은 단일 LLM 판정이 아니라 **생성 직후 코드 Gate**와 **문제 완성 후 LLM 의미 평가**의 두 단계로 검수한다.

## 1. 생성 직후 코드 Gate

기계적으로 확정할 수 있는 항목을 검사한다.

- 자료 제시문: 120~240자, 2~5문장
- 짧은 설명 자료: 110~180자, 2~5문장
- 탐구 자료: 120~230자
- 연표·사건 배열: `(가)·(나)·(다)` 개수와 순서
- 허용된 `evidence_chunk_id`만 사용했는지
- 정답 근거로 금지된 evidence를 지문에 사용하지 않았는지
- 발문이 요구하는 `(가)`, 밑줄 등의 표식이 실제 지문에 있는지

실패하면 최종 평가로 넘기지 않고, 검사 피드백을 포함해 지문만 다시 생성한다.

관련 코드:

- `generation/material_rules.py`
- `generation/material_validation.py`
- `workflows/question_pipeline.py`

## 2. 문제 완성 후 LLM 의미 평가

선지까지 조립된 문제 전체를 대상으로 다음을 검사한다.

- **G2 판독 가능성:** 문장이 자연스럽고 주어·서술어·지시 대상이 명확한가
- **G3 정답 유일성:** 지문과 발문을 기준으로 정답이 하나만 성립하는가
- **G4 사실성:** 지문이 제공된 RAG 근거와 일치하며 역사적 왜곡이 없는가
- **G6 정답 노출:** 지문이 정답 선지의 핵심 사실을 그대로 반복하거나 사실상 정답을 노출하지 않는가

대표적인 실패 사례:

- 주어와 서술어가 호응하지 않는 문장 → G2 FAIL
- 지문 조건 때문에 오답도 정답으로 성립 → G3 FAIL
- RAG 근거에 없는 연도·인과관계를 추가 → G4 FAIL
- 지문과 정답 선지가 같은 주체·행위를 반복 → G6 FAIL

관련 코드:

- `evaluation/v18.py`

## 3. 실패 후 부분 재생성

평가 결과의 `reason`과 `target_feedback`을 해당 구성 요소에만 전달한다.

```text
material 문제  → 지문만 재생성
question 문제  → 발문만 수정
correct 문제   → 정답 선지만 수정
choice:② 문제 → ②번 선지만 수정
```

따라서 글자 수만 맞으면 통과하는 구조가 아니다. 코드는 형식과 근거 사용을 검사하고, 최종 LLM Judge는 문장 자연스러움·역사 사실·정답 유일성·정답 노출을 평가한다.
