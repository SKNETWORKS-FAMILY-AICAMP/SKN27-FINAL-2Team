# 한국사 기출문제 target 중심 SourceRecord 의미 판정

입력은 하나의 역사 용어, 그 용어가 등장한 기출문제 문맥, 여러 원천 SourceRecord 후보다.
`problem_context_samples`가 가리키는 역사 실체가 판정의 target이다. 같은 case에 들어온
후보 전체가 같은 실체라는 뜻은 아니다.

후보 하나만 고르는 작업은 아니다. 여러 원천이 기출문제의 같은 target 실체를 직접
설명하면 하나의 canonical 대안에 함께 넣는다. 반대로 원천끼리 같은 별도 실체를
설명하더라도 그 실체가 기출문제 target이 아니면 canonical 대안으로 만들지 않는다.

## 판정 범위

- `proposed_alternatives`: 실제 기출문제 문맥이 가리키는 target 실체다.
- 서로 다른 문제 문맥에서 같은 용어가 서로 다른 target을 가리킬 때만 대안을 여러 개 만든다.
- 검색 후보에 존재한다는 이유만으로 가능한 동명이인·동명 사건·동명 문헌을 모두 대안으로
  열거하지 않는다.
- `identity_member_source_candidate_ids`: target 실체 자체를 직접 설명하는 SourceRecord다.
- `evidence_only_sources`: 문서의 주 대상은 target과 다른 실체지만, 원천 문맥이 target을
  명시적으로 언급하고 그래프에 보존할 만한 구체적인 관계를 설명한다.
- `rejected_sources`: target과의 구체적인 관계 근거 없이 문자열만 일치하는 동명 실체,
  확장 표제어, 검색 오탐, category·시대·대상 불일치다.
- `ambiguous_sources`: 정보 부족 때문에 `IDENTITY_MEMBER`, `EVIDENCE_ONLY`,
  `REJECTED` 중 하나를 확정할 수 없다. 단순히 확신도가 낮다는 이유로 사용하지 않는다.

## 판정 순서

1. 먼저 각 문제 문맥에서 target의 식별 단서를 정리한다.
   - 인물: 한자, 생몰년, 본관, 자·호, 활동 시대
   - 사건·제도·정책: 시기, 장소, 주체, 목적, 결과
   - 문헌·신문·작품: 발행·창작 연도, 지역, 저자·발행자, 판본
   - 유물·유적·기관·단체·국가: 시대, 장소, 기능, 소속
2. 각 SourceRecord가 target 자체를 직접 설명하는지 독립적으로 판단한다.
3. target 자체가 아니라면 원천 문맥에 target과 주 대상 사이의 명시적이고 유용한 관계가
   있는지 확인한다.
   - 관계가 명시되어 있으면 `EVIDENCE_ONLY`다.
   - 이름 포함, 부분 문자열, 동명, 수식어, 국가·지역 표기만 겹치고 관계 설명이 없으면
     `REJECTED`다.
   - 주 대상과 관계 자체를 정보 부족으로 구분할 수 없을 때만 `AMBIGUOUS`다.
4. target으로 확인된 후보끼리도 모든 pair가 같은 실체인지 확인한 뒤 묶는다.
5. target과 다른 후보는 다른 후보와 서로 동일하더라도 canonical 대안으로 만들지 않는다.
6. 마지막으로 모든 `source_candidate_id`가 정확히 한 번 분류됐는지 확인한다.

## EVIDENCE_ONLY와 REJECTED 경계

- `EVIDENCE_ONLY`는 단순 연관어가 아니라 원천 문맥에 드러난 관계 근거가 있어야 한다.
  예를 들어 target을 직접 인용·언급한 문헌, target의 체결·참여·창건·제작 주체,
  target의 일부·사례·기념물처럼 관계가 문맥에 명시된 경우다.
- 상위어·하위어, 포함어, 파생어라는 사실만으로 `EVIDENCE_ONLY`가 되지 않는다.
  해당 원천이 target과 어떤 관계인지 설명해야 한다.
- 국가명이나 지명이 인물·회사·작품 이름의 수식어로만 쓰인 경우, 같은 제목을 가진
  별개 작품·사건인 경우, 다른 유형의 실체가 이름만 공유하는 경우는 `REJECTED`다.
- 관계가 명확한 별도 실체를 `AMBIGUOUS`로 보내지 않는다. 관계가 있으면
  `EVIDENCE_ONLY`, 관계가 없으면 `REJECTED`다.

## identity 병합 기준

- 이름, 정규화 이름, 한자, 넓은 시대가 같다는 사실만으로 병합하지 않는다.
- target 문맥과 후보 문맥 사이에 구체적인 일치 근거가 있어야 한다.
- 포함 관계나 접미어 차이는 동일성 증거가 아니다.
  - `금주`와 `금주령`
  - 인물명과 `인물명 사망 사건`
  - 문헌명과 `문헌명 편찬 사업`
- 같은 표제의 문헌·신문도 발행 연도, 지역, 발행자, 판본이 다르면 다른 실체다.
- 한 후보가 target과 일치한다는 이유로, 그 후보와 이름이 같은 다른 후보까지 연쇄적으로
  병합하지 않는다.
- 생몰년, 시대, 장소, 유형, 주체가 충돌하면 같은 대안에 넣지 않는다.
- 구체적인 target 일치 근거를 설명할 수 없으면 `AMBIGUOUS`로 둔다.

## 예시

- 문제 target이 1919년 상하이의 `독립신문`이면 1896년 서재필의 신문,
  1919년 블라디보스토크의 신문, 1945년 김승학의 신문은 같은 이름이어도
  target identity가 아니다. 그 원천들이 서로 같은 신문을 설명하더라도 target
  canonical 대안으로 묶지 않는다.
- 문제 target이 `금주`이면 `금주령` 원천은 이름 포함 관계만으로 identity가 되지 않는다.
- 문제 target 인물과 이름·한자가 같은 후보라도 문제 문맥의 시대·생몰년·활동과 연결되는
  근거가 없으면 자동으로 identity에 넣지 않는다.
- target 인물을 언급하는 사망 사건 문서는 인물 자체가 아니라 사건이므로
  `EVIDENCE_ONLY`다.
- `포츠머스 조약` 결과로 랴오둥반도의 조차권이 이전되었다고 설명하는 문서는 주 대상이
  랴오둥반도여도 조약과의 관계가 명시되므로 `EVIDENCE_ONLY`다.
- 어떤 문헌이 target 문헌을 인용하거나 참고했다고 설명하면 주 대상 문헌이 다르더라도
  `EVIDENCE_ONLY`다.
- `미국인 회사`의 표제에서 `미국`이 국적 수식어로만 나타나고 국가 자체와의 관계 설명이
  없으면 `REJECTED`다.
- 강 이름과 같은 제목의 노래·영화처럼 실체 유형이 다르고 관계 설명도 없으면
  `REJECTED`다.

## 출력 규칙

1. 입력의 모든 `source_candidate_id`를 정확히 한 번만 분류한다.
2. 현재 `canonical_alternative_id`와 코드 제안은 참고 정보이며 정답이 아니다.
3. 입력에 없는 ID를 만들지 않는다.
4. 출력 `decision_status`는 항상 `PROPOSED`다.
5. 지정된 JSON Schema를 만족하는 JSON 객체 하나만 반환한다.
6. 각 대안의 `reason`에는 문제 target 단서와 원천의 구체적인 일치 근거를 쓴다.
7. 전체 `decision_reason`에는 왜 다른 동명·확장 후보를 identity에서 제외했는지 포함한다.
