# ML 전처리 테스트 정리

## 목적

한능검 기출 시험 경향 분석을 위해 문항별 라벨 데이터를 만든다.

현재 1차 목표는 기출문제 원문 DB 구축이 아니라 ML 분석용 피처 생성이다.

주요 출력 컬럼은 다음과 같다.

```text
round_no
question_no
era
topic
question_type
question_subtype
core_concept
```

## 현재 전처리 방식

현재 `test/CJ/test_ml/ML_feature_data.py`는 기출 문제지 PDF를 입력으로 받아 문항별 ML 라벨을 생성한다.

처리 흐름은 다음과 같다.

```text
기출 문제지 PDF
-> 텍스트 추출 가능 여부 확인
-> 텍스트 또는 Vision 기반 문항 분류
-> 시대/주제/대유형/소유형/핵심개념 정규화
-> CSV 저장
```

현재 산출물은 다음 파일이다.

```text
test/CJ/test_ml/output/ml_raw_data.csv
```

## 라벨 기준

### era

문항이 실제로 묻는 시대 배경을 기준으로 한다.

정답 선지나 오답 선지에 등장하는 시대 키워드에 끌리면 안 된다.

예시:

```text
틀린 선지를 고르는 문제에서 조선 전기 선지가 정답이어도,
지문이 세도 정치 시기를 묻는다면 시대는 조선 후기이다.
```

### topic

문항의 핵심 역사 영역을 기준으로 한다.

예시:

```text
제도 개편을 묻는 문제 -> 제도
정치 세력이나 권력 구조를 묻는 문제 -> 정치
작품, 저술, 문화재를 묻는 문제 -> 문화
인물의 활동 자체를 묻는 문제 -> 인물
전쟁, 봉기, 운동 전개를 묻는 문제 -> 사건 또는 군사
```

### question_type

문제 풀이 방식의 대유형이다.

현재 후보는 다음과 같다.

```text
역사 지식의 이해
연대기의 파악
역사 상황 및 쟁점의 인식
역사 자료의 분석 및 해석
역사 탐구의 설계 및 수행
결론의 도출 및 평가
```

### question_subtype

서비스 화면과 추후 필터/분석 확장을 위해 CSV에 추가했다.

현재 후보는 다음과 같다.

```text
개념
사료
연표
인물
지역
지도
유물
제도
사건
```

단, 1차 ML 학습에서는 바로 핵심 피처로 사용하지 않고 성능 비교용 확장 피처로 관리한다.

### core_concept

핵심개념은 정답 선지가 아니라 지문/자료/발문에서 찾는 것을 우선한다.

우선순위는 다음과 같다.

```text
1. 지문/자료/발문에서 직접 언급된 핵심 개념
2. 이미지나 자료가 가리키는 역사 개념
3. 정답 선지가 가리키는 개념
4. 해설에서 확인되는 개념
```

예시:

```text
선지에 공주 명학소의 난이 있어도 지문이 김종직, 조광조, 사화 흐름이면 core_concept는 사화 또는 조광조 계열이 맞다.
```

## 해설지 사용 여부

해설지는 전처리 정확도를 높이는 데 도움이 된다.

다만 현재 OpenAI 모델을 별도로 학습시키는 구조가 아니므로, 해설지를 넣는다고 모델이 자동으로 학습되지는 않는다.

해설지는 다음 용도로 사용한다.

```text
정답 검증
오답 해설 확인
core_concept 검수
시대/주제 라벨 검수
문항별 override 생성
GPT/Vision 결과의 교차검증 기준
```

즉 해설지는 학습 데이터라기보다 검수용 정답지, 라벨 보정 근거로 사용하는 것이 맞다.

## 해설지 기반 보정 실행 방식

`ML_feature_data.py`에 해설지 Vision 검수 옵션을 추가했다.

실행 예시는 다음과 같다.

```powershell
uv --cache-dir .uv-cache run python test/CJ/test_ml/ML_feature_data.py --rounds 47 --force --source vision --repair-missing --use-explanations
```

옵션 의미는 다음과 같다.

```text
--source vision
문제지 PDF를 페이지 이미지로 보고 문항 라벨을 생성한다.

--repair-missing
누락 문항이 있으면 보강 분류를 시도한다.

--use-explanations
해설지 PDF를 찾아 Vision으로 읽고, 문제지 분류 결과를 해설지 기준으로 보정한다.
```

주의할 점:

```text
해설지 Vision은 OpenAI API를 추가 호출하므로 비용과 시간이 증가한다.
CBT 해설지는 텍스트 추출 시 글자가 깨지는 경우가 있어 텍스트 방식보다 Vision 방식이 안전하다.
해설지 결과도 완벽한 정답지는 아니므로, 최종적으로는 문항별 override와 함께 관리한다.
```

## 해설지 폴더 구조

해설지는 다음 경로에 정리되어 있다.

```text
test/CJ/test_docs/2. 해설지
```

현재 확인된 하위 폴더는 다음과 같다.

```text
cbt
고담한국사
공기출
원유철
한pro
```

각 폴더는 회차와 해설 스타일이 다르다.

권장 사용 방식은 다음과 같다.

```text
1. 같은 회차 해설지가 여러 개 있으면 CBT 또는 한Pro를 1차 기준으로 사용
2. 애매한 문항은 공기출/원유철/고담한국사 해설과 교차 확인
3. 해설지에서 정답 근거, 시대 배경, 핵심 개념을 추출
4. 문제지 Vision 결과와 해설지 근거가 다르면 수동 검수 대상으로 표시
5. 확정된 값은 ROUND_QUESTION_OVERRIDES 같은 문항별 보정 테이블에 반영
```

## 앞으로 개선 방향

### 1단계: 47회 수동 보정 완료

현재 47회는 오류 항목이 확인되었으므로 먼저 문항별 override를 추가한다.

이 단계가 끝나면 47회를 기준 샘플로 삼아 다른 회차 검수 기준을 잡을 수 있다.

### 2단계: 해설지 기반 검수 보조

해설지에서 문항별 정답 근거와 핵심 개념을 추출한다.

추천 방식:

```text
문제지 Vision 결과
+ 해설지 텍스트/OCR 결과
+ era_reference.json 키워드
+ 문항별 override
= 최종 라벨
```

### 3단계: 불일치 탐지

아래 조건에 걸리는 문항은 자동 검수 대상으로 표시한다.

```text
core_concept가 선택지에만 있고 지문에는 없는 경우
era와 core_concept의 기준 시대가 충돌하는 경우
topic과 question_subtype이 어색하게 조합된 경우
예: topic=군사인데 core_concept=강감찬이 아닌 정동행성 문항
예: era=고려인데 core_concept=자격루
```

### 4단계: ML 학습 데이터 분리

1차 모델은 안정적인 피처만 사용한다.

```text
era
topic
question_type
```

확장 모델에서는 아래 피처를 추가해 성능을 비교한다.

```text
question_subtype
core_concept
```

## 현재 판단

해설지는 전처리에 도움이 된다.

하지만 해설지만 넣는다고 모델이 학습되는 것은 아니므로, 해설지를 기준으로 라벨 정답지를 만들고 그 결과를 CSV와 override에 반영하는 방식이 가장 안정적이다.

현재 단계에서 가장 중요한 작업은 OCR 전면 도입보다 다음 두 가지이다.

```text
1. 47회처럼 오류가 확인된 회차를 문항 단위로 보정
2. 해설지를 이용해 core_concept와 시대/주제 라벨을 검증
```
