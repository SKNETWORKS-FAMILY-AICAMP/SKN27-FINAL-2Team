# 한능검 기출문제 속성 자동 분류 및 출제 경향 분석 기획안 v2

## 1. 프로젝트 개요

### 프로젝트명

머신러닝 기반 한국사능력검정시험 기출문제 속성 자동 분류 및 출제 경향 분석 시스템

### 목표

한능검 기출문제의 지문과 질문을 기반으로 문제의 속성을 자동 분류한다.

분류 대상은 다음 4가지이다.

- 시대
- 주제
- 대유형
- 소유형

분류된 결과를 회차별로 집계하여 출제 경향을 분석하고, 이후 다음 회차의 출제 가능성이 높은 시대, 주제, 유형을 추정하는 데 활용한다.

## 2. 핵심 전략

기존에 검토했던 방식은 `시대 x 주제` 조합을 각각 이진 분류하는 방식이었다.

예를 들어 시대 8개, 주제 10개를 조합하면 총 80개의 조합이 생기고, 각 조합마다 별도 이진 분류 모델을 만드는 구조이다.

하지만 이 방식은 데이터 희소성과 운영 복잡도가 크다.

따라서 본 프로젝트에서는 다음과 같은 독립형 멀티 클래스 분류 구조를 사용한다.

```text
Model 1: 시대 예측
Model 2: 주제 예측
Model 3: 대유형 예측
Model 4: 소유형 예측
```

각 모델은 같은 입력 데이터를 사용하지만, 서로 다른 정답 라벨을 예측한다.

## 3. 데이터셋 구조

최종 학습용 데이터셋은 다음 컬럼을 가진다.

```text
round_no
question_no
input_text
keywords
era
topic
question_type
question_subtype
core_concept
```

### 컬럼 설명

| 컬럼명 | 역할 | 설명 |
| --- | --- | --- |
| `round_no` | 메타데이터 | 시험 회차 |
| `question_no` | 메타데이터 | 문항 번호 |
| `input_text` | 학습 입력 | 지문과 질문을 합친 원문 텍스트 |
| `keywords` | 보조 학습 입력 | 참고 사전 기반으로 추출한 핵심 역사 용어 |
| `era` | 예측 라벨 | 문제의 시대 |
| `topic` | 예측 라벨 | 문제의 주제 |
| `question_type` | 예측 라벨 | 문제의 대유형 |
| `question_subtype` | 예측 라벨 | 문제의 소유형 |
| `core_concept` | 검수/해석용 | 문제의 핵심 개념 |

## 4. 학습 입력과 예측 대상

### 학습 입력 X

모델이 실제로 학습에 사용하는 입력은 다음과 같다.

```text
input_text + keywords
```

`input_text`는 주 입력 데이터이고, `keywords`는 보조 입력 데이터이다.

`keywords`는 모델에 반드시 넣어야 하는 정답 컬럼이 아니라, `input_text`에서 핵심 역사 용어를 뽑아 모델이 참고할 수 있게 만든 보조 특성이다.

### 예측 라벨 y

모델이 예측해야 하는 정답 라벨은 다음 4개이다.

```text
era
topic
question_type
question_subtype
```

### 분석 및 검수용 컬럼

다음 컬럼은 모델 입력으로 직접 사용하지 않고, 데이터 관리와 결과 해석에 사용한다.

```text
round_no
question_no
core_concept
```

## 5. input_text 구성 기준

`input_text`는 다음 두 요소만 사용한다.

```text
material + question
```

즉, 지문과 질문만 사용한다.

선택지는 1차 학습 입력에서 제외한다.

### 선택지를 제외하는 이유

오답 선지에는 의도적으로 다른 시대와 주제의 키워드가 포함된다.

예를 들어 고려 문제의 오답 선지에 조선, 삼국, 일제 강점기 관련 키워드가 들어갈 수 있다.

이 경우 선택지를 모두 입력에 넣으면 모델이 실제 문제의 시대와 주제를 혼동할 수 있다.

또한 `옳지 않은 것은?`, `적절하지 않은 것은?` 같은 부정형 문제에서는 정답 선지 자체가 틀린 설명일 수 있다.

따라서 1차 모델에서는 선택지를 제외하고, 지문과 질문만 사용한다.

## 6. keywords 생성 방식

`keywords`는 `input_text`에서 참고 사전 기반으로 추출한 핵심 역사 용어이다.

참고 사전 후보는 다음과 같다.

```text
test/CJ/test_docs/3. 참고 자료/시대별_인물_전처리.json
test/CJ/test_docs/3. 참고 자료/시대별_인물_정리_v2_1.json
```

예시:

```text
input_text:
공민왕은 쌍성총관부를 공격하고 기철 등 친원 세력을 제거하였다.

keywords:
공민왕 쌍성총관부 기철 친원 세력
```

`keywords`는 `core_concept`와 동일한 값이 아니라, `input_text`에서 자동 추출한 핵심어 목록이어야 한다.

## 7. 원천 데이터 활용 계획

### 사용할 원천 파일

```text
test/CJ/test_ml/han_v41_47-78.json
```

이 파일은 팀원이 만든 SLLM용 데이터셋이다.

구조상 선택지 기준으로 전처리되어 있으며, 5개의 레코드가 하나의 문제를 의미한다.

```text
1번째 레코드:
발문 + 정답 선지 생성용

2~5번째 레코드:
오답 선지 생성용
```

### 문제 단위 재구성 방식

5개 레코드를 하나의 문항으로 묶는다.

다만 학습 입력에는 선택지를 넣지 않고, 공통으로 포함된 다음 정보를 사용한다.

```text
material
question
topic
major_type
minor_type
question_task
```

## 8. 라벨 정의

### era

문제의 시대를 나타낸다.

1차 모델에서는 조선 전기와 조선 후기를 통합한다.

```text
조선 전기 -> 조선
조선 후기 -> 조선
```

통합 이유는 다음과 같다.

- 데이터 수를 늘려 모델 안정성을 높일 수 있다.
- 조선 전기/후기 경계가 애매한 문제가 존재한다.
- 추후 필요하면 `era_detail` 컬럼으로 다시 세분화할 수 있다.

### topic

문제의 주제 영역을 나타낸다.

예시:

```text
정치
경제
사회
문화
인물
군사
외교
사상·종교
제도
사건
```

### question_type

문제의 대유형을 나타낸다.

원천 데이터의 `major_type`을 기준으로 사용한다.

예시:

```text
역사 지식의 이해
연대기의 파악
역사 상황 및 쟁점의 인식
역사 자료의 분석 및 해석
역사 탐구의 설계 및 수행
결론의 도출 및 평가
```

### question_subtype

문제의 소유형을 나타낸다.

컬럼명은 `question_subtype`으로 유지하지만, 값은 원천 데이터의 `minor_type` 정의를 사용한다.

예시:

```text
자료 기반 시대·대상 추론
전후 시기 판단
기본 사실·개념 확인
사건·자료 순서 배열
시각 자료 해석
제도·기관·정책 기능 이해
```

## 9. 모델 구조

본 프로젝트는 4개의 독립형 멀티 클래스 분류 모델을 사용한다.

```text
Model 1: input_text + keywords -> era
Model 2: input_text + keywords -> topic
Model 3: input_text + keywords -> question_type
Model 4: input_text + keywords -> question_subtype
```

각 모델은 동일한 입력을 사용하지만 서로 다른 라벨을 예측한다.

## 10. 추천 알고리즘 v2

v2에서는 학습한 머신러닝 알고리즘을 중심으로 비교 실험을 진행한다.

텍스트 데이터는 모델이 바로 이해할 수 없으므로, `input_text`와 `keywords`를 숫자 특성으로 바꾸는 전처리는 필요하다.

다만 기획안에서는 특정 벡터화 방식에 고정하지 않고, 아래 알고리즘들을 비교 대상으로 둔다.

### 1순위: LightGBM

추천 이유:

- 학습 속도가 빠르다.
- 데이터가 많아져도 비교적 안정적으로 학습할 수 있다.
- 여러 클래스 분류에 사용할 수 있다.
- 시대, 주제, 유형처럼 범주가 여러 개인 문제에 적용하기 좋다.

### 2순위: XGBoost

추천 이유:

- 분류 성능이 강한 대표적인 부스팅 모델이다.
- 클래스 간 패턴 차이가 뚜렷할 때 좋은 성능을 기대할 수 있다.
- LightGBM 결과와 비교하기 좋은 기준 모델이 된다.

### 3순위: CatBoost

추천 이유:

- 범주형 데이터 처리에 강점이 있다.
- 텍스트를 전처리한 뒤 범주형 보조 특성과 함께 사용할 때 비교 가치가 있다.
- 다만 실행 환경과 설치 부담이 있을 수 있어 1차보다는 비교 실험용으로 둔다.

### 4순위: Random Forest

추천 이유:

- 모델 구조가 비교적 이해하기 쉽다.
- 과적합 여부와 특성 중요도 확인에 참고하기 좋다.
- 다만 텍스트 기반 고차원 특성에서는 부스팅 계열보다 성능이 낮을 수 있다.

### 5순위: Gradient Boosting

추천 이유:

- 부스팅 개념을 이해하고 비교하기 좋은 기본 모델이다.
- 데이터 규모가 작을 때 실험해볼 수 있다.
- 다만 LightGBM, XGBoost보다 학습 속도와 성능 면에서 불리할 수 있다.

### 추천 실험 순서

```text
1. Random Forest로 기본 분류 가능성 확인
2. Gradient Boosting으로 부스팅 계열 기본 성능 확인
3. LightGBM으로 주력 모델 성능 확인
4. XGBoost로 LightGBM과 비교
5. CatBoost는 환경이 가능하면 추가 비교
```

최종 선택은 단순히 정확도만 보고 결정하지 않고, 학습 속도, 설명 가능성, 재현 가능성, 팀원이 실행하기 쉬운지도 함께 고려한다.

## 11. 평가 방법 v2

본 프로젝트는 분류 모델이므로 다음 평가 지표를 사용한다.

| 지표 | 설명 | 사용 이유 |
| --- | --- | --- |
| Accuracy | 전체 예측 중 정답을 맞힌 비율 | 전체적인 성능을 빠르게 확인할 수 있다. |
| Precision | 특정 클래스로 예측한 것 중 실제로 맞은 비율 | 모델이 특정 시대나 유형이라고 예측했을 때 얼마나 믿을 수 있는지 확인한다. |
| Recall | 실제 특정 클래스인 것 중 모델이 맞힌 비율 | 특정 시대나 유형을 놓치지 않고 잘 잡아내는지 확인한다. |
| F1-Score | Precision과 Recall의 조화평균 | 데이터 불균형이 있을 때 정밀도와 재현율을 함께 평가할 수 있다. |
| Macro F1 | 클래스별 F1을 동일한 비중으로 평균낸 값 | 문항 수가 적은 시대나 유형도 공정하게 평가할 수 있다. |
| Weighted F1 | 클래스별 F1을 데이터 수에 따라 가중 평균한 값 | 전체 데이터 분포를 반영한 종합 성능을 확인할 수 있다. |
| Confusion Matrix | 실제 라벨과 예측 라벨의 혼동 관계를 표로 나타낸 것 | 어떤 시대나 유형을 서로 헷갈리는지 확인할 수 있다. |
| AUC-ROC | 여러 임계값에서 분류 성능을 확인하는 지표 | 이진 분류에는 유용하지만, 현재처럼 멀티 클래스 분류에서는 우선순위를 낮춘다. |

### 핵심 지표

핵심 평가지표는 `Macro F1`로 한다.

한능검 데이터는 시대와 주제별 문항 수가 균등하지 않다.

예를 들어 조선, 근현대 문항은 상대적으로 많고, 선사 시대나 초기 국가는 상대적으로 적을 수 있다.

이런 상황에서 Accuracy만 보면 데이터가 많은 클래스에 유리한 착시가 발생한다.

따라서 클래스별 성능을 균등하게 반영하는 Macro F1을 핵심 지표로 사용한다.

### 보조 지표

```text
Accuracy
Precision
Recall
Weighted F1
Confusion Matrix
```

`AUC-ROC`는 이번 프로젝트의 핵심 지표로 두지 않는다.

이유는 현재 목표가 단순한 참/거짓 이진 분류가 아니라, 시대, 주제, 대유형, 소유형을 각각 여러 클래스 중 하나로 고르는 멀티 클래스 분류이기 때문이다.

필요하다면 특정 라벨을 따로 이진 분류로 분석할 때 보조적으로 사용할 수 있다.

## 12. 출제 경향 분석 방식

문항별 속성 분류가 완료되면 회차별로 결과를 집계한다.

분석 항목:

```text
회차별 시대 분포
회차별 주제 분포
회차별 대유형 분포
회차별 소유형 분포
시대 x 주제 조합 분포
시대 x 대유형 조합 분포
```

이후 최근 N개 회차의 흐름을 바탕으로 다음 회차 출제 경향을 분석한다.

예시:

```text
최근 5회차에서 고려-정치 문항 비율 감소
최근 5회차에서 일제 강점기-사회 운동 문항 증가
최근 5회차에서 연대기의 파악 유형 반복 출제
```

## 13. 1차 구현 목표

```text
1. han_v41_47-78.json을 5개 단위로 묶어 문제 단위 데이터로 변환
2. material + question으로 input_text 생성
3. 참고 사전 기반 keywords 생성
4. era, topic, question_type, question_subtype 라벨 정리
5. 조선 전기/후기 라벨을 조선으로 통합
6. core_concept는 검수/해석용으로 유지
7. ml_yj_train_data.csv 생성
8. Random Forest, Gradient Boosting, LightGBM, XGBoost, CatBoost 비교 실험
9. Macro F1과 Confusion Matrix로 성능 확인
```

## 14. 기대 결과

최종적으로 기출문제의 지문과 질문만 입력해도 다음 속성을 자동으로 분류할 수 있다.

```text
시대
주제
대유형
소유형
```

그리고 분류 결과를 누적하면 한능검 출제 경향을 정량적으로 분석할 수 있다.

분석 가능한 질문:

```text
어떤 시대가 자주 출제되는가?
어떤 주제가 반복되는가?
어떤 문제 유형이 증가하는가?
최근 회차에서 빠진 영역은 무엇인가?
다음 회차에서 나올 가능성이 높은 조합은 무엇인가?
```

현재 v2 기준으로는 선택지를 제외하고, 지문과 질문만 학습 입력으로 사용하는 방식이 가장 안정적이다.

## 15. 번외: 예측 모델과 문제 생성 연결 고민

출제 경향 분석 모델이 안정화되면, 예측 결과를 문제 생성에도 활용할 수 있다.

예를 들어 최근 회차에서 특정 시대나 주제가 적게 출제되었거나 다시 출제될 가능성이 높다고 판단되면, 문제 생성 조건에 해당 경향을 반영할 수 있다.

다만 이 기능은 바로 적용하기보다 다음 사항을 먼저 검토해야 한다.

- 모델이 예측한 경향이 실제로 신뢰할 만한가?
- 단순히 많이 나온 유형을 반복 생성하는 문제가 생기지 않는가?
- 사용자의 취약 유형과 최신 출제 경향을 어떻게 함께 반영할 것인가?

따라서 v2에서는 "예측한 모델로 문제 생성에 최신 트렌드를 적용할 수 있는지 검토" 정도로 남기고, 실제 구현은 모델 성능 검증 이후 진행한다.

## 16. 예측 모델을 사용하는 이유

예측 모델의 목적은 다음 회차 문제를 정확히 맞히는 것만이 아니다.

더 중요한 목적은 기출문제 데이터를 기반으로 사용자의 다음 학습 행동을 정할 근거를 만드는 것이다.

### 1. 출제 경향을 숫자로 설명할 수 있다

기존에는 "근현대가 많이 나오는 것 같다", "문화 문제가 자주 나오는 것 같다"처럼 감각적으로 판단할 수밖에 없었다.

예측 모델과 회차별 통계를 사용하면 다음과 같이 설명할 수 있다.

```text
최근 5회차에서 일제 강점기 비중 증가
최근 5회차에서 문화 유형 비중 감소
최근 5회차에서 연대기의 파악 유형 반복 출제
```

즉, 출제 경향을 주관적인 느낌이 아니라 데이터 기반으로 설명할 수 있다.

### 2. 문제 추천 기준으로 사용할 수 있다

예측 결과는 사용자가 풀 문제를 추천하는 기준이 될 수 있다.

단순히 랜덤으로 문제를 주는 것이 아니라 다음 요소를 함께 고려할 수 있다.

```text
최근 출제 가능성이 높은 시대
최근 자주 등장하는 주제
사용자가 자주 틀리는 유형
```

예시:

```text
사용자 약점: 고려 정치
최근 출제 경향: 고려 제도 문항 증가
추천 문제: 고려 정치/제도 중심 문제
```

이렇게 하면 문제 추천이 단순 랜덤이 아니라, 출제 경향과 사용자 취약점을 함께 반영한 추천이 된다.

### 3. 학습 계획을 더 구체적으로 만들 수 있다

학습 플래너에서 단순히 "오늘 20문제 풀기"로 끝나는 것이 아니라, 어떤 문제를 풀어야 하는지까지 정할 수 있다.

예시:

```text
오늘은 출제 가능성이 높은 개항기/일제 강점기 문제 10개
취약한 연대기 유형 문제 5개
반복 출제되는 문화재 문제 5개
```

즉, 예측 모델은 학습 계획을 개인화하고 구체화하는 근거가 된다.

### 4. SLLM 문제 생성 조건으로 사용할 수 있다

추후 파인튜닝된 SLLM이 문제를 생성할 때, 예측 모델의 결과를 문제 생성 조건으로 사용할 수 있다.

예시:

```text
최근 출제 경향을 반영해서
시대: 조선
주제: 정치
유형: 연대기의 파악
난이도: 중
문제를 생성한다.
```

이렇게 하면 생성 문제도 무작위 생성이 아니라, 최신 출제 경향을 반영한 문제 생성으로 확장할 수 있다.

### 5. 결과 화면과 노트 분석에도 활용할 수 있다

사용자가 틀린 문제를 단순히 오답으로만 저장하는 것이 아니라, 출제 경향과 연결해 해석할 수 있다.

예시:

```text
최근 자주 출제되는 유형인데 틀린 문제
최근 출제 가능성은 낮지만 사용자가 반복해서 틀리는 문제
반복 출제되는 핵심 개념에서 발생한 오답
```

이를 통해 오답노트와 학습 통계가 단순 기록이 아니라 학습 전략을 제안하는 기능으로 확장될 수 있다.

### 정리

예측 모델의 장점은 단순히 다음 회차를 맞히는 것이 아니다.

핵심은 다음 기능에 사용할 근거 데이터를 만드는 것이다.

```text
문제 추천
학습 계획
문제 생성
결과 분석
오답노트 개선
```

따라서 본 프로젝트에서 예측 모델은 "정답을 맞히는 모델"보다 "학습 방향을 정하는 분석 모델"에 가깝다.
